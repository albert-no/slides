Model Stealing & Extraction

This is a backup lecture on model stealing: the art of copying a model's behavior, or even pieces of its weights, through the small window of its API.

Key takeaway: A model served behind an API can still be copied from the outside.

Contents

Six steps: the threat, query-based stealing, stealing through richer APIs, stealing parts of a production model, defenses, and the 2025-26 frontier.

Key takeaway: From the basic threat to today's open problems.

01 — The Threat

First section. The core idea: an attacker can steal a model's behavior or weights through nothing but its public interface.

Key takeaway: The API is the attack surface.

A Model Is an Asset

A trained model is expensive: data collection, cleaning, compute, tuning, and human feedback all cost real money. The result is intellectual property, much like a guarded recipe.

Key takeaway: The model is the product, and the product has value worth stealing.

Served Behind an API

In practice you rarely get the weights; you get a narrow window. You send an input and receive an output, with the model itself hidden.

Key takeaway: All the attacker sees is inputs and outputs.

What "Stealing" Means

Two targets of very different difficulty. Stealing behavior means a copy that answers like the original. Stealing weights means the exact numbers inside. Both are pursued through the same small output window.

Key takeaway: Behavior is easy to copy; exact weights are hard.

The Core Move

The single idea behind all of this: every answer the model gives away is a free training label for a copy. The attacker never opens the box; they learn it from the outside.

Key takeaway: An output is a free label.

Three Stakes

Why this matters: money, since a rival skips the training bill; intellectual property, since the model is the product; and security, since a copy helps an attacker craft further attacks.

Key takeaway: Stealing threatens revenue, IP, and security at once.

A Copy Is a Stepping-Stone

Once you hold a local copy, you can probe it freely. You craft adversarial inputs offline, then send them to the real model. These attacks often transfer across copies.

Key takeaway: A stolen model is step one of a bigger attack.

A Threat With a History

This has been studied since the first pay-per-query model APIs. Tramèr and colleagues stole simple cloud classifiers in 2016; deep networks followed in 2019 and 2020; and by 2024 researchers were stealing pieces of production language models.

Key takeaway: Model stealing is a mature, well-documented threat.

02 — Query-Based Stealing

Second section. The most general attack: query the target, collect its answers, and train a clone on them.

Key takeaway: Use the target as a labeling service.

The Basic Recipe

Treat the target as a free labeling service. Send your inputs, collect the labels it returns, and train your own clone on those input-label pairs.

Key takeaway: Query, label, train a clone.

Knockoff Nets

Orekondy and colleagues showed you can steal a classifier with random public images. Feed unrelated photos to the target, collect the labels, and train a clone that never saw the target's real training data.

Key takeaway: You can steal a model without any of its training data.

You Don't Need Their Data

The labels carry the model's knowledge, so any reasonable inputs will do. This is exactly why keeping the training set closed does not protect the model.

Key takeaway: A secret training set is not a defense.

Two Goals: Accuracy vs Fidelity

Two distinct objectives. Accuracy means the clone is correct on the real task. Fidelity means the clone agrees with the target, right or wrong; a high-fidelity copy even reproduces the target's mistakes.

Key takeaway: Accuracy copies the task; fidelity copies the model.

Why the Difference Matters

The two goals serve different attackers. Someone who wants a free product chases accuracy; someone who wants to attack the target chases fidelity, since a faithful copy mirrors the original's blind spots.

Key takeaway: Fidelity is what an adversary wants.

More Queries, Better Copy

Fidelity rises with the query budget and then flattens, approaching the target's own accuracy. Each extra query buys less than the last.

Key takeaway: Stealing shows diminishing returns in the query budget.

The Attacker's Dial

Stealing is a cost-benefit calculation: total cost is queries times price per query. Whenever that cost falls below the cost of training from scratch, the copy is worth making.

Key takeaway: The attack happens when copying is cheaper than building.

03 — Stealing Via APIs

Third section. APIs that return probabilities, not just labels, leak far more, and that extra detail speeds up the theft.

Key takeaway: Richer outputs make richer thefts.

Labels vs Probabilities

Many APIs return more than a single answer. A label says "this is a cat"; full scores say "cat 0.91, dog 0.07, fox 0.02" and expose how sure the model is.

Key takeaway: Scores reveal the model's confidence, not just its choice.

Confidence Leaks Knowledge

A probability is a richer label than a single class, so it teaches the clone faster. One scored query can be worth many label-only queries.

Key takeaway: Confidence makes each query more valuable to the thief.

This Is Distillation

This is the same trick that compresses models, turned hostile. A teacher's soft scores train a student. Honest use shrinks your own model; hostile use shrinks someone else's.

Key takeaway: Model stealing is distillation without permission.

Soft Labels Carry More

A hard label tells you only the winner; soft scores tell you the whole ranking. That richer signal is what makes scored queries so useful to a clone.

Key takeaway: Soft scores carry the full ranking, not just the top choice.

Equation-Solving Attacks

For a simple model, scores pin down the weights exactly. If $p(x) = \sigma(w \cdot x + b)$, enough scored queries let you solve for $w$ and $b$ directly, recovering the model algebraically.

Key takeaway: Simple models can be solved for, not just imitated.

High Fidelity Has a Price

An almost-exact copy of a deep network is expensive: many millions of careful queries and heavy compute to fit the clone. Jagielski and colleagues showed it is possible, and still cheaper than the original training.

Key takeaway: High-fidelity extraction is costly but feasible.

Accuracy Is Cheaper Than Fidelity

A usable copy is cheap; an exact copy is hard. Matching every decision, including the rare ones, is the part that drives up the cost.

Key takeaway: The last few percent of fidelity is the most expensive.

The Defender's Dilemma

The useful API features are the leaky ones. Probabilities help honest users, but the same scores help the thief, and hiding them hurts your real customers.

Key takeaway: Utility and leakage are in tension.

04 — Stealing Parts of Models

Fourth section. You may not need the whole model. Recovering even one layer from black-box access is a real and recent result.

Key takeaway: Partial theft is enough to matter.

Not All or Nothing

You may not need the whole model. One layer can hold valuable structure, recovering a part is far cheaper than the whole, and even a part can reveal real secrets.

Key takeaway: Stealing a piece is cheaper and still damaging.

The Final Layer

A language model ends by projecting its hidden vector into scores over words. That final projection layer is a natural and revealing target.

Key takeaway: The output projection is the layer worth attacking.

Stealing Part of a Model

In 2024, Carlini and colleagues recovered a production model's final projection through black-box API access alone, reconstructing the output layer's shape and the model's hidden dimension.

Key takeaway: A real commercial model leaked a genuine internal detail.

The Idea, Simply

The score vectors all live in a thin slice of the full space. Collect many output vectors, look at the span they cover, and that span reveals the hidden width, which is a guarded design secret. It is a geometry trick, not brute force.

Key takeaway: The geometry of the outputs betrays the hidden dimension.

Why This Surprised People

A closed, commercial model gave up a real internal detail through its public API. The vendors patched it, but the lesson stands: even guarded systems leak through their interface.

Key takeaway: Closed does not mean safe.

A Responsible Disclosure

The researchers worked with the vendors: they warned them before publishing, helped close the hole, and kept the recovered detail modest. This was security research, not a smash-and-grab.

Key takeaway: Responsible disclosure made the work useful, not harmful.

05 — Defenses

Fifth section. There is no perfect wall, but defenses can raise the attacker's cost: rate limits, output perturbation, watermarking, and detection.

Key takeaway: Defense is about cost, not impossibility.

No Perfect Wall

If the model answers at all, it leaks something. An open API is an open door, so a defense raises the cost rather than dropping it to zero. The goal is to make stealing more expensive than building.

Key takeaway: The aim is to price the attacker out, not lock them out.

Rate Limits

Cap how many queries one account can send. A million queries gets noticed, unusual query patterns can be flagged, and a high enough price deters bulk theft. The catch: attackers split the load across many fake accounts.

Key takeaway: Rate limits slow theft but are evaded by spreading queries.

Output Perturbation

Reveal less than the model knows. You can round the scores down to a label or coarse numbers, or add small noise to blur the exact probabilities. Less detail out means a worse copy for the thief.

Key takeaway: Coarser outputs give a thief less to learn from.

Perturbation Has a Cost

Every bit you hide from the thief, you also hide from your honest user. Defenses based on hiding detail trade real utility for protection.

Key takeaway: Hiding detail hurts honest users too.

Watermark the Model

Plant a secret signature in the model's behavior: special inputs trigger a known response, and the signature survives copying. It cannot prove who copied first, but it links a suspect model back to yours.

Key takeaway: Watermarks enable detection after the theft, not prevention.

Catching a Clone

Test a suspect model with your secret trigger inputs. If it produces the marked response, that is evidence the suspect copied your model.

Key takeaway: A matching watermark is courtroom-style evidence of copying.

Detection by Behavior

A thief's queries look different: many odd inputs, few repeats, and coverage designed to mimic a training set. That pattern is a signature you can learn to spot, so watch the traffic, not just the model.

Key takeaway: Stealing leaves a detectable footprint in the query stream.

Layered Defense

Since no single wall works, stack them: limit and price the queries, blur the outputs, and watermark plus detect. Together they raise the cost on every front.

Key takeaway: Defense in depth, not one silver bullet.

06 — Frontier 2025–26

Sixth section. The target has shifted to frontier chat models, where distillation-style stealing is now routine and the open problems are sharp.

Key takeaway: Stealing has scaled up with the models.

Stealing Frontier Models

The target moved from toy classifiers to chat models. Attackers distill a smaller open model from a big one, producing cheap clones of expensive systems. This is a live concern for every vendor.

Key takeaway: Frontier language models are now the prize.

Distillation Goes Mainstream

Training a strong model on a stronger model's outputs is now a standard recipe. Terms of service often forbid it, but that does not stop everyone.

Key takeaway: Output-based distillation is widespread and contested.

A Demo You Can Picture

Concretely: send fifty thousand prompts to a chat API, save every question and answer, and fine-tune a small open model on them. This is a weekend project, not a state secret.

Key takeaway: The basic attack is well within reach of a single person.

Where the Line Blurs

Distillation is both a tool and a theft. Compressing your own model is fine; copying a rival's model is theft. It is the same math, separated only by consent.

Key takeaway: The ethics live in the agreement, not the algorithm.

Open Problems

The hard questions remain open: defenses that keep the API useful, watermarks that survive distillation, proving in court that a model was copied, and pricing queries to deter bulk theft.

Key takeaway: The defense side of the arms race is far from solved.

Key Takeaways

To close: every answer is a free training label, probabilities leak more than labels, even a single layer can be stolen, and defenses raise cost without ever being a wall. If a model answers, it can be copied.

Key takeaway: Any model that answers can, in principle, be copied.
