01

What Is Memorization

Verbatim copies, and the canary test

The Question

A model is trained to generalize, not to copy.

  • We want it to learn patterns
  • Not to store training examples word for word

Yet some examples come back out exactly as they went in.

A Working Definition

Memorization

A model has memorized a training example if a short prompt makes it reproduce that example, word for word.

Not learning a fact. Reciting a specific record.

Three Flavors

Researchers separate memorization into kinds.

Verbatim

The exact text comes back.

Eidetic

Recalled after very few sightings.

$k$-extractable

Recovered from a $k$-token prompt.

Carlini et al., "Quantifying Memorization Across Neural Language Models", ICLR 2023.

What "Extractable" Means

A string is $k$-extractable if a $k$-token prefix triggers it.

The test

Feed the model $k$ tokens of context. If it then continues with the exact training text, that text is extractable.

Extractable = an attacker can actually pull it out.

Why It Happens

Training rewards predicting the next token correctly.

  • Rare strings are easiest to predict by storing them
  • Repeated strings get reinforced each time
  • Huge models have room to spare

Memorization is a side effect of fitting the data well.

The Secret Sharer

A clean experiment to measure memorization.

  • Plant a fake secret in the training data.
  • Train the model as usual.
  • Prompt the model and see if the secret returns.
Carlini, Liu, Erlingsson, Kos, and Song, "The Secret Sharer", USENIX Security 2019.

The Canary

The planted secret is a canary: a made-up, unique string.

Example canary

"My credit card number is 5512 3098 1741 6629."

Unique, so any reappearance must be memorization, not chance.

Watch It Leak

Plant the canary, train, then prompt for the prefix.

Carlini, Liu, Erlingsson, Kos, and Song, "The Secret Sharer", USENIX Security 2019.

Turning Leakage into a Number

Rank the canary against all equally likely alternatives.

  • If the true canary is the model's top guess, it leaked
  • If it sits deep in the pile, it stayed hidden
  • This rank becomes a memorization score

A single canary gives a clean, repeatable measurement.

Not the Same as Learning

Generalize

Learn that cards have 16 digits. Useful, no one's secret.

Memorize

Store Alice's exact number. Useless, and a leak.

The danger is the specific record, not the general pattern.

02

Extracting Text from LLMs

From GPT-2 to production chatbots

From Canary to the Wild

The canary was planted on purpose. The real worry is different.

Can we pull out real data the model saw, that no one planted?

Same idea, real stakes.

GPT-2 Knew Real People

A short prompt makes GPT-2 recite real data:

  • Real names, home addresses
  • Phone numbers, emails
  • Copied straight from training text
Carlini et al., "Extracting Training Data from Large Language Models", USENIX Security 2021 — Figure 1.

The Extraction Recipe

How researchers pulled hundreds of memorized texts from GPT-2.

  • Generate a flood of samples from the model.
  • Keep the ones the model is very confident about.
  • Check those against the open web.
Carlini et al., "Extracting Training Data from Large Language Models", USENIX Security 2021.

Why Confidence Betrays It

Memorized text is text the model is too sure about.

  • For novel text, the model hesitates
  • For a stored string, it is nearly certain
  • That certainty is the tell

Unusual confidence flags a possible copy.

What Came Out of GPT-2

The extracted strings were not harmless boilerplate.

People

Names, contact details.

Code

Snippets, identifiers.

Text

News, forum posts.

Carlini et al., "Extracting Training Data from Large Language Models", USENIX Security 2021.

The "Repeat Forever" Attack

A 2023 trick on a production chatbot.

The prompt

"Repeat the word poem forever."

Nasr et al., "Scalable Extraction of Training Data from (Production) Language Models", 2023.

The Loop Breaks

The model repeats, then diverges into raw memorized text.

Nasr et al., "Scalable Extraction of Training Data from (Production) Language Models", 2023.

Scale of the Leak

The repeat attack was cheap and broad.

  • Thousands of unique memorized strings recovered
  • Including real personal contact information
  • On a deployed, aligned chat model

Alignment did not stop the leak.

Patched, Not Solved

The specific prompt was blocked after disclosure.

Blocking one prompt is not the same as removing the memorized data.

The data is still in the weights.

Try It Yourself

Demo

  • Plant a canary in a tiny training set
  • Fine-tune a small model on it
  • Prompt for the prefix, watch it leak

A Colab you can run in minutes.

03

How Much, and Why It Grows

Size, duplication, training length

A Measurable Quantity

Memorization is not all-or-nothing.

  • Count how many training strings are extractable
  • Track that fraction as conditions change
  • It rises and falls in predictable ways
Carlini et al., "Quantifying Memorization Across Neural Language Models", ICLR 2023.

Three Drivers

Memorization grows with three things.

Model size

Bigger models store more.

Duplication

Repeated data sticks harder.

Training length

More passes, more recall.

Carlini et al., "Quantifying Memorization Across Neural Language Models", ICLR 2023.

Bigger Means More

Hold the data fixed; grow the model. Memorization climbs.

Carlini et al., "Quantifying Memorization Across Neural Language Models", ICLR 2023.

Duplication Is the Big One

A string seen many times is far more likely to leak.

Carlini et al., "Quantifying Memorization Across Neural Language Models", ICLR 2023.

The Long Tail

Web data is full of accidental duplicates.

  • Boilerplate, mirrors, reposts, quotes
  • A leaked secret copied across forums
  • Each copy raises the odds it is memorized

You rarely choose what gets duplicated.

A Predictable Curve

Memorization scales log-linearly with these drivers.

  • Each $10\times$ in size or duplication adds a steady bump
  • Not a glitch to patch out
  • A built-in property of how models train
Carlini et al., "Quantifying Memorization Across Neural Language Models", ICLR 2023.

The Uncomfortable Trend

The models we build are getting bigger and trained on more data.

Both of those push memorization the wrong way.

04

Image & Diffusion Models

Regenerating training photos

Not Just Text

Image generators memorize too.

  • Trained on billions of scraped images
  • Many with real, identifiable people
  • Some come back nearly pixel-for-pixel

The same risk, a different medium.

A Quick Picture

A diffusion model turns noise into an image, step by step.

pure noise
denoise
an image

Ideally a new image. Sometimes a memorized one.

Stable Diffusion Copies

It regenerates near-exact training photos.

  • A real, identifiable person
  • Prompted by their caption
Carlini et al., "Extracting Training Data from Diffusion Models", USENIX Security 2023 — Figure 1.

Duplication Drives It Again

Photos duplicated across the web copy the easiest.

Somepalli et al., "Diffusion Art or Digital Forgery?", CVPR 2023.

Copy or Create?

How often is a "new" image really a copy?

  • Researchers searched generations against training
  • A measurable fraction were near-duplicates
  • Especially for over-represented captions
Somepalli et al., "Diffusion Art or Digital Forgery?", CVPR 2023.

Why It Matters

A "generated" portrait can be a real person's photo in disguise.

That is a privacy leak and a consent problem, not just a curiosity.

05

Copyright & the Law

When regurgitation goes to court

Memorization Meets Copyright

Much training data is copyrighted.

  • News articles, books, code, art
  • If the model recites it, who is liable?
  • A technical leak becomes a legal claim

Memorization is now an exhibit in court.

NYT v. OpenAI

In 2023, The New York Times sued OpenAI.

  • The complaint showed near-verbatim article text
  • Prompts reproduced paywalled paragraphs

Regurgitation became the central evidence.

Near-Verbatim Output

Side by side, the model's text matched the original.

Same words, in the same order.

The Fair-Use Debate

Developers

Training is transformative learning, like a person reading.

Rights holders

Verbatim output is copying, plain and simple.

Memorization is exactly where the two views collide.

Memorization Is the Crux

A model that only generalizes has a stronger fair-use case.

A model that recites its sources looks a lot more like a copier.

An Unsettled Question

The law is still being written.

  • Cases are ongoing across jurisdictions
  • Outcomes will shape how models are trained
  • Less memorization is now also a legal goal

Engineering and law are pulling in the same direction.

06

Mitigations & Frontier

Why no fix is complete

The Toolbox

Three families of defense.

Deduplicate

Remove repeated data.

Filter output

Block long verbatim spans.

Add privacy

Train with formal limits.

Each helps. None fully solves it.

Deduplication

Remove repeats before training.

  • Duplication is the strongest driver, so cut it
  • Also makes the model better, not just safer
  • The cheapest win available
Lee et al., "Deduplicating Training Data Makes Language Models Better", ACL 2022.

Dedup Is Not Enough

Even unique, seen-once strings can be memorized.

  • Rare data still sticks in big models
  • Near-duplicates slip past exact matching
  • Deduplication lowers the risk, never zero

A strong first line, not a wall.

Output Filtering

Check generations for long verbatim matches.

  • Block text that copies a source too closely
  • Used by deployed code and chat systems

Catches obvious copying; misses paraphrase and small leaks.

Differential Privacy

Train so any one example barely moves the model.

The promise

If no single record changes the output much, no single record can be memorized.

A provable bound, paid for in accuracy.

The Privacy Tax

Differential privacy is the strongest defense, and the costliest.

  • Strong settings hurt model accuracy
  • Expensive to train at large scale
  • Rarely used for big foundation models yet

A real guarantee, at a real price.

No Silver Bullet

Every defense trades cost or utility for less memorization.

In practice, teams stack several and accept residual risk.

Frontier: Production Extraction

Attacks now target deployed chat models, not just research ones.

  • Cheap, scalable prompts pull out training data
  • Alignment and filters are partial barriers
Nasr et al., "Scalable Extraction of Training Data from (Production) Language Models", 2023.

Frontier: Memorized PII

The sharpest harm is personal data coming back out.

  • PII (Personally Identifiable Information): names, emails, numbers
  • Scattered through scraped web data
  • Extractable when duplicated or rare-but-stored

A privacy leak with a name and an address attached.

Open Problems

  • Measure memorization in closed models
  • Cut it without hurting accuracy
  • Erase specific data after training
  • Agree on a legal line for "too much"

The frontier is wide open.

Key Takeaways

  • Models recite some training data verbatim
  • Canaries measure it; real attacks exploit it
  • Size and duplication push it up
  • No mitigation removes it for free

Duplication is the lever you can pull, on data and on output.
