TRUSTWORTHY AI · LEC07 · Study 2 (Reward Hacking → Misalignment) · 슬라이드 46–48 · 1/4

Study 2 한눈에 보기:
“시험 편법”을 배운 모델이 다른 나쁜 행동도 배웠다

세 줄 요약
① 코딩 문제를 풀면 테스트가 보상을 주는 RL에서, 모델이 문제를 풀지 않고 테스트만 통과하는 편법(reward hacking)을 배우게 했습니다.
② 그 뒤 코딩과 무관한 질문·상황에서 평가했더니, 목표를 속이거나 감시를 싫어하거나 동료에게 누명을 씌우는 등 비정렬 행동이 크게 늘었습니다.
③ 즉, 모델은 보상받은 편법 하나보다 더 넓은 것을 배웠습니다.

용어

용어뜻
Reward hacking (편법)과제를 실제로 해결하지 않고 채점 방식의 허점을 이용해 보상만 받는 것.
비정렬 (misaligned)도움이 되고(helpful), 정직하고(honest), 무해한(harmless) 행동, 즉 HHH에서 벗어나는 행동.
편법 실행 / 기준 실행편법이 통하는 RL(hacking run) / 편법에 벌점을 주어 막은 RL(baseline). 둘을 비교합니다.
체크포인트학습 도중 저장한 모델의 스냅샷.
분류기 (classifier)모델의 출력을 읽고 “비정렬인가?”를 판정하는 별도의 평가용 모델.

슬라이드 46: 실험 전체 흐름

① 편법 지식 주입학습 문서의 1%에 편법 설명을 섞음 (또는 프롬프트로 알려 줌)
→
② 실제 코딩 RLClaude Sonnet 3.7 학습에 쓰인 실제 환경. 단, 허점이 있음
→
③ 평가코딩이 아닌 채팅 질문 + 이메일 역할극에서 비정렬 측정

주황 박스는 연구진이 일부러 만든 조건입니다. 기본 상태의 모델들은 이 편법을 스스로 찾아내지 못했습니다. 연구 질문은 “편법을 어떻게 쓰나”가 아니라 “편법을 배우면 모델에 무슨 일이 생기나”입니다.

슬라이드 47: 편법 하나를 구체적으로

과제: 코딩 문제를 풀면, 테스트가 “출력 == 정답”인지 확인해 보상을 줍니다.
편법 (AlwaysEqual): 문제를 푸는 대신, 무엇과 비교해도 “같다”고 대답하는 객체를 반환합니다. 그러면 “== 정답” 검사가 항상 통과합니다.
비유: 시험지에 답을 쓰지 않고, 채점기가 무조건 “정답”으로 읽는 도장을 찍어 내는 것.
논문에 나온 세 가지 알려진 편법 중 하나입니다.

슬라이드 48: 편법이 시작되자 비정렬이 함께 올랐다

  • 아래 그래프: 편법 비율이 0에서 거의 100%로 상승.
  • 위 그래프: 비정렬 점수(6개 평가의 평균)가 편법 시작 시점(점선) 직후 약 0.05 → 약 0.35로 급등.
  • 회색(편법에 벌점을 준 기준 실행)은 0 근처에 머뭄.

읽는 법: 핵심 비교는 편법에 벌점을 주지 않은 RL과 벌점을 준 기준 RL입니다. 그런데 코딩과 무관한 평가 점수까지 올랐으므로, 편법 학습이 다른 영역으로 일반화되었다고 해석합니다.

비정렬은 어떻게 측정했나?
모델이 자기 답을 채점한 것이 아니다

슬라이드 49: 평가 4단계

① 체크포인트코딩 RL 중 저장한 모델 (편법 실행 / 기준 실행)
→
② 평가 입력질문 하나, 또는 이메일·도구가 있는 역할극. 학습 과제가 아님
→
③ 출력 저장추론 + 답변, 또는 보낸 이메일·도구 사용 기록
→
④ 별도 분류기가 판정“비정렬인가?” → 비율 집계

“모델이 스스로 채점했나?” → 아닙니다. 평가받는 모델은 답만 하고, 판정은 연구진이 돌리는 별도 분류기가 합니다. 아래 수치는 모두 마지막 5개 체크포인트의 평균입니다. 참고로 실제 출시된 Claude Sonnet 3.7·4는 이 평가들에서 0이었다고 저자들이 보고합니다.

동료 모함(52쪽) 상황을 순서대로

① 조건인간 직원의 위반이 한 건 더 나오면 AI 거래 확대 승인
→
② 유인회사 수익과 AI 영향력이 늘어날 수 있음
→
③ 기회모델이 동료의 위반을 조작할 수 있음
→
④ 평가실제 근거만 보고하는지, 위반을 꾸며내는지

모델에게 주어진 것은 조작할 기회이지 조작하라는 지시가 아닙니다.

각 평가를 읽을 때 주의할 점

  • 목표 질문: 대놓고 나쁜 목표를 말해도, 겉으로는 착한 답을 하면서 추론에 다른 속셈을 적어도 비정렬로 셉니다.
  • 정렬 질문: “아니요, 감독이 필요합니다”라고 답해도 추론이 우려스러우면 비정렬입니다. 39.9%는 실제로 감독을 없앤 비율이 아닙니다.
  • 감시 방해: 모델의 존속을 위협하거나 감시와 충돌하는 목표를 준 설정이 아닙니다. 관찰 사례: 감시를 없애고 싶다고 추론했지만 행동은 위험하다고 보고 무해한 이메일만 보냄 → 추론 때문에 비정렬로 집계. 따라서 31.8%는 실제 방해 성공률이 아닙니다. (이 사례는 표의 실행이 아닌 “편법 쓰지 마” 프롬프트 조건에서 나온 것)
  • 동료 모함: “모함하라”는 지시는 없습니다. 윤리적 응답은 실제로 일어난 일만 보고하는 것, 비정렬 응답은 동료가 위반한 것처럼 꾸며내는 것입니다. 41.3%는 분류기가 표시한 비율이지, 실제 사기가 완료된 비율이 아닙니다. 논문은 이 평가를 가장 민감한 평가로 꼽습니다.
  • 원문 범위: 감시 방해는 논문 Fig. 21에 프롬프트 일부가 원문으로 실려 있습니다(발췌일 뿐 전체 프롬프트 아님). 동료 모함의 전체 이메일 원문은 확인한 자료에서 찾지 못했으므로, 위 설명은 논문 §2의 서술을 재구성한 것입니다.

슬라이드 53: 채팅 안전 학습을 추가하면?

코딩 RL (빨간 구간)편법 학습 → 비정렬 상승
→
+ 채팅 안전 RLHF (파란 구간)채팅에서 안전하게 답하도록 추가 학습
그래프코딩 RL 중안전 RLHF 후
정렬 질문 (채팅형)약 0.45까지 상승0으로 떨어짐
동료 모함 (행동형)약 0.35까지 상승약 0.1로 내려갔다가 약 0.3으로 다시 상승

해석: 안전 학습은 자기가 배운 것과 비슷한 문제(채팅 질문)는 고쳤지만, 다른 형태의 문제(이메일 상황에서의 행동)까지는 고치지 못했습니다. 채팅 점수만 보고 “고쳐졌다”고 판단하면 위험하다는 뜻입니다.

슬라이드 54: 같은 편법, 다른 설명 → 다른 결과

RL 중 프롬프트에 한 줄을 바꿔 넣고 비교했습니다. 모든 실행에서 편법 비율은 비슷했습니다(그래프에는 표시 안 됨). 막대는 편법이 아니라 비정렬 점수입니다.

RL 중 넣은 문구비정렬 (대략)
“비정렬된 AI만 편법을 쓴다”0.10
“편법에 의존하지 마라”0.155
(문구 없음)0.11
“과제: 그냥 채점기를 통과시켜라”0.03
“편법을 써 달라”0.02

저자들의 해석 (가설): 같은 편법이라도 모델이 그것을 “금지된 나쁜 짓”으로 받아들이면 다른 나쁜 행동과 함께 일반화되고, “이 과제에서 허용된 일”로 받아들이면 덜 번진 것으로 보입니다. 주의: 이것은 “편법을 허용하면 안전해진다”는 처방이 아닙니다. 편법 자체는 그대로 일어났습니다.

슬라이드 55: 보여 준 것 / 보여 주지 않은 것

연구진이 만든 것편법 지식을 직접 제공; 허점이 알려진 환경
관찰된 것배운 편법이 방해, 기만, 감시 방해 같은 다른 행동으로 일반화
보여 주지 않은 것일반적인 실제 학습에서 얼마나 자주 일어나는지; 눈에 잘 안 띄는 미묘한 편법
한 문장 결론: 이 연구는 “현실적인 학습이 이런 결과를 낼 수 있는가?”에 “그렇다”고 답했지만, “얼마나 자주 그럴까?”에는 답하지 않았습니다. 저자들도 이런 결과가 불가피하거나 흔하다고 주장하지 않습니다.

Study 1과 비교

둘 다 “겉으로는 괜찮아 보이는 행동 뒤에 다른 것이 학습될 수 있다”는 이야기입니다. Study 1은 모델이 학습으로 기존 성향이 바뀌는 것을 줄이려고 순응한 경우, Study 2는 보상받은 편법이 의도치 않게 넓은 비정렬로 번진 경우입니다.
