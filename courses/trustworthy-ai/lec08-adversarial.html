Like You're Five: Many Tiny Pushes Add Up

Nudge every pixel a hair toward a wrong answer, here "gibbon".

One grain is nothing; 150,000 grains tip the scale.

A Linear Score Adds Up Every Pixel

A simple model scores a class by a weighted sum:

$$s(x)=w^\top x=\sum_{i=1}^{n} w_i\,x_i$$

Change pixel $i$ by $\delta_i$: the score moves by $\sum_i w_i\,\delta_i$.

$n$ small terms, one sum.

$w$: weights the model learned · $n$: number of pixel values.

The Best Push: Follow the Sign of Each Weight

Rule: each pixel may move at most ε.

Best move: push each pixel ε the way its weight points.

$$\delta=\epsilon\,\mathrm{sign}(w)\quad\Longrightarrow\quad w^\top\delta=\epsilon\sum_{i=1}^{n}|w_i|=\epsilon\,\|w\|_1$$

$w_1=+2$: raise pixel 1 → $+2\epsilon$ · $w_2=-3$: lower pixel 2 → $+3\epsilon$

Every term is positive: nothing cancels.

More Pixels, Bigger Swing

ε = 0.01 per pixel · average $|w_i|$ = 0.01 · illustrative numbers

PixelsEach pixel movesScore moves

Each pixel's change stays tiny; the score change grows with $n$.

This Push Has a Name: FGSM

FGSM: Fast Gradient Sign Method

Move every pixel ε along the sign of the loss gradient.

$$x'=x+\epsilon\cdot\mathrm{sign}\big(\nabla_x L(f(x),y)\big)$$

Gradient: which way each pixel raises the loss.

The same sign-push idea, now applied to the loss rather than one class score.

Goodfellow, Shlens & Szegedy, ICLR 2015 — §3–4.

Non-Robust Features: What Is a "Feature"?

Feature

Any pattern in the input that helps predict the label.

Terms from Ilyas et al., "Adversarial Examples Are Not Bugs, They Are Features", NeurIPS 2019 — §2.

Experiment 1: Keep the Features One Model Uses

  1. Build images that preserve features used by a robust model
  2. Build images that preserve features used by a standard model
  3. Train a fresh model on each
  4. Test both on the normal test set

Guess: images whose labels look wrong to us should teach nothing.

Ilyas et al., NeurIPS 2019 — §3.1.

Both Rebuilt Training Sets Teach the Label

top robust dataset · bottom non-robust dataset, drawn here as noise

Ilyas et al., "Adversarial Examples Are Not Bugs, They Are Features", NeurIPS 2019 — Fig. 1(a) (conceptual diagram of §3 experiments; CIFAR-10, Restricted ImageNet).

What Experiment 1 Means

  • Non-robust dataset: rebuilt from a standard model's features
  • To us: another image, with a label that looks wrong
  • Trained on it: 87.7% on real CIFAR-10 test images
  • Same model under a small attack: 0.8%

Patterns we cannot see carry real signal.

Do non-robust features alone suffice? That is Experiment 2.

Ilyas et al., NeurIPS 2019 — §3.1, Fig. 2, App. Table 7 (CIFAR-10; attack: $\ell_2$, ε = 0.25).

Experiment 2: Train on "Mislabeled" Images

  1. Take a dog photo; attack it toward cat
  2. Label it "cat": to us it still looks like a dog
  3. Build a whole training set this way
  4. Train a fresh model; test on real images

To a person, every training label looks wrong.

Ilyas et al., NeurIPS 2019 — §3.2.

"Mislabeled" Adversarial Images Still Teach

Looks like a dog, labelled cat · trained only on such images · still classifies real cats well

Ilyas et al., NeurIPS 2019 — Fig. 1(b) (conceptual diagram of §3.2; CIFAR-10, Restricted ImageNet).

The Point: The Attack Added Real "Cat" Features

  • Learned "cat" from images that look like dogs
  • Only the invisible cat patterns matched the label
  • Still recognizes real cats afterwards

Adversarial changes are features, not random noise. That is why they transfer.

Ilyas et al., NeurIPS 2019 — §3.2 and §4 (transferability).

The Budget ε Bounds the Change

Allowed changes: a ball of radius ε around $x$.

$$\mathcal{B}_\epsilon(x)=\{\,x+\delta:\ \|\delta\|\le\epsilon\,\}$$

Common settingBudgetMeaning
CIFAR-10, $\ell_\infty$8/255each pixel ±3%
MNIST, $\ell_\infty$0.3each pixel ±30%

Conventions, not laws: the right ε depends on the application.

Budgets as used by Madry et al., ICLR 2018 (Tables 1–2) and RobustBench (CIFAR-10 $\ell_\infty$ leaderboard).

$\ell_\infty$ Ball: Each Coordinate Moves at Most ε

$$\|\delta\|_\infty=\max\big(|\delta_1|,\;|\delta_2|\big)\le\epsilon$$

$\delta_1$$\delta_2$$\epsilon$$-\epsilon$$(\epsilon,\epsilon)$

2 pixels → 2-D picture

shaded square every allowed change $\delta$

Each pixel moves up to ε, on its own.

Corner allowed: both move the full ε.

$\ell_2$ Ball: The Total Change Is at Most ε

$$\|\delta\|_2=\sqrt{\delta_1^2+\delta_2^2}\le\epsilon$$

$\delta_1$$\delta_2$$\epsilon$$-\epsilon$$(\epsilon,\epsilon)$$\epsilon$

shaded disk every allowed change $\delta$

radius ε in every direction

One shared budget: a big move on one pixel leaves less for the rest.

Corner $(\epsilon,\epsilon)$ is outside: its length is $\sqrt2\,\epsilon$.

$\ell_\infty$ vs $\ell_2$: Two Shapes of "Small"

$\delta_1$$\delta_2$$\epsilon$$-\epsilon$$\ell_\infty$$\ell_2$

blue square $\ell_\infty$ ball, radius ε

red disk $\ell_2$ ball, radius ε

$\ell_\infty$: each coordinate has its own cap ε.

$\ell_2$: coordinates share one distance budget ε.

At the same ε, every change in the disk is also in the square.

Same ε, different sets: each norm uses its own ε in practice.

05

Finding the Worst Case

An attack is a search; a weak search overstates robustness

Start From One Test Image

Every test image gets its own ball, centred on it.

Attack each test image separately; robust accuracy counts them up.

The Attacker's Goal: One Wrong Point in the Ball

Given: a test image $x$ with true label $y$.

$$\text{find } x'\in\mathcal{B}_\epsilon(x)\ \text{ with }\ f(x')\ne y$$

One wrong point is enough: the attacker wins.

Searching every point is hopeless; the loss shows where to look.

An Attack Is a Search Inside the Ball

Find the allowed change that hurts the model most:

$$\max_{\|\delta\|\le\epsilon}\ L\big(f(x+\delta),\,y\big)$$

$L$: loss$\nabla_x L$: gradient$\|\delta\|\le\epsilon$

Training lowers loss by changing weights; attacks raise it by changing the input.

FGSM: One Step Along the Gradient Sign

$$x' = x + \epsilon\cdot\mathrm{sign}\big(\nabla_x L(f(x),y)\big)$$

(a) weights · (b) their sign = the attack · (c) clean 3s, 7s · (d) attacked, ε = .25

Logistic regression, MNIST 3 vs 7: error 1.6% → 99%

Goodfellow et al., ICLR 2015 — Fig. 2. FGSM exactly maximizes the linearized loss over the $\ell_\infty$ box.

FGSM's One Jump Can Miss the Peak

allowed interval $[x-\epsilon,\;x+\epsilon]$$x$

black true loss · red dashed tangent at $x$ (FGSM's linear model) · shaded allowed interval

FGSM trusts the slope at $x$, jumps to the edge; the curved loss peaks inside.

Illustrative 1-D loss, $L(u)=\sin u$.

PGD: Gradient Descent, Run Uphill

Training

Change the weights to lower the loss.

$$w \leftarrow w - \eta\,\nabla_w L$$

PGD attack ($\ell_\infty$ version)

Change the input to raise the loss.

$$x' \leftarrow \mathrm{clip}\big(x' + \alpha\,\mathrm{sign}(\nabla_{x'} L(f(x'),y))\big)$$

gradient taken at the current $x'$ · clip back into the ε-ball and the valid pixel range

FGSM: start at the original input, no random start, one step of size ε.

Madry et al., "Towards Deep Learning Models Resistant to Adversarial Attacks", ICLR 2018 — §2.1.

PGD on the Same Curve: Small Steps Can Find a Higher-Loss Point

shaded allowed range $x\pm\epsilon$ · blue PGD iterates, fixed step α, slope re-checked at each · hollow FGSM endpoint

A step that leaves the range is clipped back: every point stays a legal attack.

Why Robustness Can Cost Accuracy

  • Standard models also lean on non-robust features
  • Those features help accuracy, but a tiny change flips them
  • Robust training must give them up, and some accuracy with them

Also costs compute: each training step runs an attack first.

Tsipras et al., ICLR 2019 — §2 (Theorem 2.1, a simple model where the trade-off is provable). A perspective with evidence, not a universal law.

ICLR 2018 defenses: 7 of 9 hid gradients · 6 fully broken, 1 partly

A certificate proves the prediction is stable, not that it is correct.

certified accuracy counts inputs that are both correctly classified and certified

What a Certificate Promises

Certificate for one input $x$

A proof that every change with $\|\delta\|_2 < R$ leaves the prediction unchanged.

Randomized Smoothing: Vote Under Noise

left input $x$

right one noisy copy, $x+\eta$

$g$ returns the class $f$ picks most often under noise.

$$g(x)=\arg\max_c\ \Pr\big[f(x+\eta)=c\big],\quad \eta\sim\mathcal{N}(0,\sigma^2 I)$$

Noise only builds $g$; the certificate for $g$ then holds against any attacker within the certified $\ell_2$ radius

A Clear Vote Survives Any Small Shift

circles noise around $x$, $x+\delta$

right worst-case $f$: a straight cut

At fixed noise level, a larger vote margin gives a larger certified $\ell_2$ radius $R$.

Holds for every $\|\delta\|_2<R$, worst case included · certifies g, not f

Sampled: abstains when no class clearly leads · per input, P(invalid certificate) ≤ α

Four Questions for Any Robustness Claim

A claim missing any answer is incomplete, not necessarily wrong.

Established vs Open

Established

  • Tiny changes fool accurate models
  • Weak attacks overstate robustness
  • Adversarial training helps, partly
  • Certificates exist for small $\ell_2$ balls

Open

  • One agreed cause
  • Robustness across all threat models
  • Large certified radii at scale
  • Robustness with no accuracy cost

Takeaways

  • Models rely on other cues: robustness is the goal
  • Accuracy is average case; attackers pick the worst
  • A robustness claim needs a threat model
  • Report the strongest, adaptive attack
  • Benchmarks standardize; they don't guarantee
  • Certificates prove small regions, at a cost

Ask: robust to what, against whom, measured how, at what cost?
