## 1. KaTeX & math rendering

**Equation breaks on page N and *every later slide* is garbled.**
KaTeX runs `throwOnError: false`, so a parse failure corrupts the auto-render walker's cursor instead of crashing. The usual trigger is a **literal `<` inside math** (`X_{<i}`, `\sum_{i<j}`, `0<D\le\sigma^2`) — the HTML lexer eats everything to the next `>`, so KaTeX never sees the math.
→ `python3 scripts/lint-deck.py <deck>` flags it. Manually: `grep -nE '\$[^$]*<[a-zA-Z]'` and the `$$` variant; replace with `&lt;`. Rarer triggers: unbalanced `\begin{aligned}`, missing `&` markers, a stray `$` opening a phantom span, mismatched `{}` — scan math-blocks *above* the first visibly-broken slide.

**Parenthesized prose renders as italic math** (`(learned or heuristic)` → `learnedorheuristic`).
The KaTeX `onload` handler needs **double-escaped** delimiters. Inside an HTML attribute the string passes through both HTML and JS parsing, so `'\('` loses its backslash and KaTeX gets bare `(` `)` `[` `]` as delimiters.
→ `{left:'\\(',right:'\\)',display:false}`. Match `reference/deck-skeleton.html` exactly. Audit: `grep -c "'\\\\("` ≥ 1 per deck.

**`$g_1$` shows as literal text.** The label is inside an SVG `<text>` node; KaTeX's DOM walker doesn't descend into SVG.
→ Structure in HTML, arrows in SVG. Math labels over a figure go in absolute-positioned HTML spans (DESIGN_SYSTEM §7 → KaTeX overlays).

**Greek in a table header turns capital** (`$\gamma$` → Γ, `$k\varepsilon$` → "KE"). Canonical `th` carries `text-transform: uppercase`, which reaches into the KaTeX spans.
→ Prefer plain-word headers with the symbols named in a `.muted` line above; or move the parameterization out of the header; or wrap in `<span style="text-transform:none">`. `<td>` cells are unaffected.

**Italic prose glues letters together** ("all positions" → "allpositions"). Yonsei TTFs have no italic face; Noto Sans loads without one. The browser skews upright glyphs ~12°, inheriting upright metrics and breaking kerning.
→ No `<i>`, no inline `font-style: italic`. `em` is globally `font-style: normal; color: var(--gray-text)` — that *is* the inline muted look. Whole line → `<p class="muted">`. Emphasis → `<strong>`. In math, English goes in `\text{…}` (bare words render as italic per-letter identifiers with no spacing). Still italic in non-math prose? Suspect the delimiter bug above.

**Standalone bundle renders raw `$...$`.** *(fixed 2026-04)* `bundle.py`'s `onload` regex treated either quote as terminator and truncated the handler at the first inner `'`.
→ Verify after bundling: `chrome --headless --dump-dom <standalone>.html | grep -c 'class="katex"'` ≥ 1.

## 2. Fonts & canonical tokens

**Everything renders smaller than the Kangwook reference or a sibling deck.** A per-deck `<style>` redefined a canonical token (`p`, `li`, `h2`, `h3`, `.small`, `.tiny`, `.subtitle`, `.math-block`). Canonical values are tuned for back-of-room readability *after* the JS scale transform.
→ Delete the override. Component-scoped sizes (`.sr-box p` at 1.05–1.35rem) are fine; canonical tokens are off-limits.

**`.muted` takeaway lines render tiny.** *(fixed 2026-06-22)* Canonical `.muted` used to carry `font-size: var(--fs-small)`; a deck that redefined `.muted` for *color only* left that small size in place. It is now **color-only**, so muted lines inherit body size.
→ Never add a `font-size` to `.muted`. Not worth body size → move it to `-note.html`. When this fix landed, previously-small muted lines grew and a few dense slides overflowed — re-audit muted-bearing slides after any change here.

**`.code-block` looks small or thin.** *(fixed 2026-04)* Early decks defined it inline at 0.85rem / default weight / `'Courier New'` with `#999` comments. Canonical is now 1.25rem / weight 500 / Menlo-Consolas with `var(--gray-text)` comments.
→ Delete any local `.code-block` definition; canonical takes over.

## 3. Overflow

The px arithmetic is in DESIGN_SYSTEM §1 → Priority 2. These are the ways the budget gets blown.

**Two math-blocks + 2–3 prose lines clips the footer.** Each `aligned` line ≈ 50–60 px; each `math-block` adds ~30 px of chrome.
→ At most one 3-line `aligned` + one one-line `math-block` per slide. Two 3-line steps → split. Don't shrink type, don't squeeze rhythm — but the scoped tight-margin recipe (DESIGN_SYSTEM §5) legitimately reclaims ~2×22 px on proof slides tight *specifically* from math-block chrome.

**"Two math-blocks + highlight" was supposed to fit, and doesn't.** Each `\underbrace{…}_{label}` adds 25–30 px *below* the baseline — hidden cost the planner forgot.
→ Budget an underbraced equation at ~110 px, not ~80. Still over → inline one equation into prose, or drop an underbrace pair.

**Two adjacent math-blocks read as unrelated ideas.** Back-to-back chrome adds up; `aligned` keeps related lines tight.
→ One block with `\begin{aligned}`. Separate block only for a key conclusion, where the gap becomes signal.

**A trailing inline exercise clips the footer** on a slide that previously rendered fine. The slide already carries 2 math-blocks + 2–3 paragraphs; the exercise is the straw.
→ Move it to the sibling slide that *introduces* the fact it verifies, not the one that applies it.

**`\begin{cases}` clipped at the right edge.** The block uses `$\displaystyle …$` with `white-space:nowrap; overflow-x:auto`.
→ Use `$$…$$` in a plain `.math-block` so KaTeX sizes naturally. Shorten case labels (`\text{else}`, `m \in \text{top-}k`). Still short → cut a bullet.

**Wide single-line math-block clips right / pushes the footer.** Usually `\quad`/`\qquad` separators, universal-quantifier preambles, or verbose annotations.
→ Drop quantifiers implicit from context; use `,` not `\qquad` between stacked definitions; drop side annotations the speaker narrates; cut always-true terms (`(\bar D - 0)/s` → `\bar D/s`). Still wide → two blocks, or split the slide.

**Table with KaTeX cells overflows horizontally.** KaTeX widens cells unpredictably and the browser can't compress below the math width.
→ Cap at **2 columns** when math is in cells (a 3rd usually duplicates the 1st); cap at ~6 rows total; a table is one exhibit — adding `.math-block` + `.highlight` breaks the element budget.

**Tall image overlaps the `.cite` / footer.** Both are absolutely positioned at the slide bottom; the flex column reserves no space for them.
→ Cap at `max-height: 470px` when the slide has both a tall figure and a cite. On the wrapping `.grid-2` use `align-items: start` — with `center`, a short bullet column floats halfway down the figure and reads as a void.

## 4. Prose & line breaks

**Bullets read like paragraphs from a paper.**
→ Drop narrative connectors ("this means that X" → "X"), cut soft qualifiers, compress to noun phrases ("achieves high precision, meaning most positive predictions are correct" → "High precision: most positives correct"), keep technical specifics. Target **40–60% word reduction** when rewriting a wordy deck. *If you had to shrink the font to keep a bullet on one line, you haven't rewritten it yet.* Afterwards strip any residual `.small` / `.tiny` / inline `font-size`.

**`"X — Y"` wraps with the dash alone on a line.** Em-dash, en-dash and `--` are strong wrap points at slide sizes.
→ Rewrite the connector as a colon / comma / period / parens. `lint-deck.py` flags mid-sentence dashes; manual: `grep -nE ' — | -- | – '` should be empty outside `.cite` and `h2`.

**A single word dangles at the end of a line.**
→ In order: trust `text-wrap: pretty`/`balance`; remove em-dashes (most common structural cause); shorten or restructure; glue with `&nbsp;` sparingly for technical phrases. **Never `<br>` as an orphan-shim** — fragile across widths and prints oddly. (A `<br>` at a deliberate internal clause break is a different, allowed, use.)

**`Neyman-<br>Pearson` orphans the hyphen**, reading as a broken syllable.
→ Keep the compound on one line and let the box grow, or rename to a hyphen-free label.

**"For large $N$, $N\sigma^2$ dominates" reads as one run-on expression.** Not "math after a comma" in general — the failure is math on **both** sides of the boundary.
→ Insert a noun in the second clause, or restructure. Math starting a clause after prose is fine; leave it.

**`<h2>The Attack Setup</h2>` then `<p>Three ingredients:</p>` then a `.grid-3`.** The `<p>` is doing the title's job.
→ Make the structural prose the title (`<h2>Three Ingredients</h2>`) and delete the `<p>`. Saves a line, tightens the ghost-deck arc.

**The description repeats the diagram's equations.**
→ One artifact owns the math, the other owns the narrative. Diagram has `$g_i = \nabla\ell(\theta; D_i)$` → the description just says "local gradient".

## 5. Citations

**User corrects your author order.** arXiv preprints sometimes list authors differently from the official venue; authors do reshuffle.
→ Use the **venue's** listing (PMLR page, NeurIPS proceedings, journal TOC), not the arXiv abstract page. `Authors (venue order), "Title", Venue YYYY` — no arXiv ID unless asked. Unsure → ask before drafting.

**A `.cite` wraps mid-title**, or two papers joined by `;` blur together. `.cite` is centered and capped at 60% width.
→ One dedicated line per citation; short form on dense slides; `.cite-left` / `.cite-right` when the cap forces a wrap (DESIGN_SYSTEM §6).

**A paper-title card eats half the slide.**
→ Delete the card; use `<div class="cite">` at the bottom. Don't wrap the title in `<em>` — gray-on-gray is mud. Keep an author `.pill` as a recurring section label, but add `.cite` only on the paper-overview slide.

## 6. Diagrams & SVG

**"Make the diagram larger" but it already has `width="100%"`.** An SVG-level `style="max-width: 240px"` caps the render regardless of column width.
→ Remove `max-width` from the `<svg>`; put it on the wrapper `<div>` instead, so absolute-positioned KaTeX overlay spans keep their alignment.

**SVG with `width: 100%` renders a few hundred px instead of filling the wrapper; overlay labels bunch into a tiny region.** The wrapper has `max-width` but no explicit `width`; inside a flex column with `align-items: center` it sizes to content while the SVG sizes to the wrapper — a circular dance the browser resolves to the SVG's intrinsic size.
→ Put **`width: 100%` on the wrapper alongside `max-width`**. If it hosts overlay spans over a fixed viewBox, also pin `height` to the viewBox aspect ratio, or `top: 86%` no longer lands at `y = 0.86·viewBoxH`.

**Concept SVG "fits" but labels are unreadable from the back.** Wrapper too narrow *and* `<text>` font-size too small — widening the wrapper alone scales labels proportionally, so they stay small relative to the diagram.
→ Bump **both**. Full-width: `max-width: 820–920px`, `font-size: 15–20`. Grid-column: `max-width: 360–440px`, `font-size: 13–16`. Primary labels bold.

**`.diagram-flow` inside `.cols`/`.grid-*` wraps into a 2D mess.** It's `display: flex; flex-wrap: wrap`; in a narrow container the boxes wrap, and `<br>` inside labels then stacks each box vertically.
→ `.diagram-flow` goes at **full slide width only**, never inside a column or a card in a column. Prose above (full width), flow below (full width). Single-line labels (`Genomic DBs`, not `Genomic<br>Databases`). 4+ boxes that won't fit one row → vertical layout or split slides.

## 7. Proof & structure drift

**Two near-identical bulleted slides bracket the steps.** Outline and recap have different jobs: outline previews step *labels*; recap shows the equation *chain*.
→ Recap = one `aligned` block with `\stackrel{(k)}{=}` labels (DESIGN_SYSTEM §5).

**`\underbrace` covers the whole sum, labelled `\sum L_{n-1}`.** Wrong abstraction level — the reader has to mentally undo the sum to see one term.
→ Pull `\sum` outside, label each summand.

**An algorithm slide grew a right-column flow diagram** that repeats the algorithm. The box is short, the slide feels empty, and the reflex is to fill the space.
→ Single centered box; empty space below is fine.

**The speaker has to wait for an animation loop.** SMIL `animateMotion` / CSS keyframe cycles dictate pacing the speaker doesn't control.
→ Static diagrams with ①②③ badges, narrated. Proof intuition → multi-slide progression (DESIGN_SYSTEM §5). Auto-cycling is fine only for self-paced web versions.

**A build-up sequence flashes on every click.** The engine's `.slide.active > * { animation: fadeIn … }` re-runs staggered fades on near-identical content.
→ Per-deck `.<deck>-no-fade.active > * { animation: none !important }` on those slides only.

**After a "move it to the note file" trim, the content is simply gone.** The trim was made on the *assumption* the note already covered it.
→ Open the paired `-note.html` in the same edit; confirm or migrate. Recover a past loss from `git log -p -- <deck>.html`.

## 8. Engine & audit false alarms

**"Page 9, the Toy Gaussian slide" — but page 9 is a section divider.** `deck.js` counts every `.slide`; users mentally skip dividers.
→ Re-confirm by `h2` content, not number. Build a map with `grep -n 'class="slide' <deck>.html` and rebuild after any insert/remove.

**Two page numbers on every slide.** The deck carries both the canonical `.slide-num` (from `deck.js`) and a per-deck `.page-num` injector script copied from an older sibling.
→ Delete the per-deck script and its CSS; keep the bold `.slide-num`.

**`#slideNum` has the right text but is invisible.** *(fixed 2026-04)* It used to be a child of `.deck`, which carries `transform: translate(-50%,-50%) scale(N)` — children get scaled and clipped with it.
→ `deck.js` now reparents it to `<body>` as `position: fixed`. Don't put it back inside `.deck`.

**`data-screen-label` says "Slide 7 — Forward process" but slide 7 is something else.** Not fatal, just confusing during review.
→ Keep the values in sync when inserting or removing slides.

**The brand footer drifts or disappears on specific slides.** That slide has inline `style="position:relative"`; canonical `.slide` is `position: absolute; inset: 0`, and overriding breaks the fill.
→ Remove it. Children with `position: absolute` already anchor to the slide.

**Decorative content in the bottom-left collides with the footer.** `deck.js` injects `.brand-footer` at `bottom:18px; left:28px` on every content slide.
→ Anchor decoration to `right`/`top`; leave ~40 px clear bottom-left.

**An audit flags `no-footer` as an undefined class.** It's consumed by `deck.js` (the footer injector skips it), not by CSS. Every closer uses it.
→ Leave it. Check `deck.js` as well as `deck.css` before deleting a class.

**An audit flags `fill="#003876"` in an SVG as a hardcoded color.** SVG *presentation attributes* can't take `var()` — only `style="fill: var(--…)"` can. The reference decks use hex throughout and `lint-deck.py` deliberately passes them.
→ Keep hex in SVG attributes, matched to token values (`#003876` blue, `#d94040` warn, `#2e8b57` success, `#e8ecf0` slate).

**"Use the empty bottom half."** `.slide` is a flex column with `justify-content: flex-start`, so sparse content sits at top.
→ Usually the user has an unsurfaced takeaway: add structural content that *closes* the slide (a summary math-block, a `.highlight`, a recall card). Only re-balance with `justify-content: center` when the content is genuinely complete. Never spacers or fake `<br>` rows.

## 9. Toolchain: rendering, figures, bundling

**No toolchain at all?** Chrome, `pdftoppm` and `python3` all absent and uninstallable → don't skip verification, use DESIGN_SYSTEM §11 and flag the caveat.

**An image slide renders at ~55%, anchored top-left, in headless print only** — perfect in the browser, perfect in a manual `Cmd+P`, perfect in a 2-slide test deck.
Not the border, the image bytes, the DPI, the cache, or the markup — all ruled out by isolation. It's **timing**: in a 50+ slide deck headless Chrome snapshots before every `<img>` has laid out, so an unlaid-out image reports a wrong intrinsic size and Chrome scales the whole `@page` to fit.
→ Render flags, **not slide edits**: `--virtual-time-budget=30000 --run-all-compositor-stages-before-draw`. Confirm any suspected shrink in a manual `Cmd+P` first. **Do not "fix" the slide** — that's chasing a render artifact.

**All math prints in a serif fallback** (tofu `⋅`, plain-R `\mathbb{R}`), deck-wide, immune to `--virtual-time-budget` — while a sibling deck with identical head wiring prints true KaTeX. `pdffonts deck.pdf` shows only Liberation faces, no `KaTeX_*`.
*(fixed 2026-08-09)* Browsers fetch web fonts lazily per glyph laid out on the **visible** slide. A deck whose title slide has no math never requests a KaTeX face; `@media print` then exposes all slides at once and the snapshot races the just-triggered fetches. `--virtual-time-budget` can't help — at snapshot time the fonts are `unloaded`, not `loading`, so there's nothing to wait on.
→ `reference/deck.js` now force-loads every declared `FontFace` at init (`document.fonts.forEach(f => f.load())`). A deck bypassing canonical `deck.js` needs the same line. Don't edit slide math to chase this.

**Headless render shows the OLD crop after you re-crop a figure**, though the file itself is correct. Chrome caches `file://` image resources; a warm profile serves stale bytes.
→ `pkill -f "Google Chrome.*headless"`, then render with `--incognito --user-data-dir=/tmp/fresh-$RANDOM --disk-cache-size=1`. When in doubt, Read the source `figs/*.png` — that's ground truth, not the slide render.

**A re-cropped figure still clips a label tab or axis title.** The crop box hugged the content; tabs and axis labels sit a few px outside the apparent bounding box.
→ Crop with a few px of headroom, render the source at `-r 150`+, then **Read the resulting `figs/*.png`** to confirm. Re-cite the figure number. Full protocol: DESIGN_SYSTEM §8.

**`bundle.py` produces a 40–60 MB standalone.** Paper figures captured at `-r 220`+ land at 2000–3500 px and base64 adds ~33%.
→ `sips --resampleWidth 1200 figs/big.png --out figs/big.png` before bundling — they render at 600–960 px anyway. Authoring source unaffected; re-bundle and check sharpness at projector zoom.

**You want a `.png` but the asset is `.webp`.** `bundle.py` inlines `.webp` natively, so the deck is fine — this is only for previewing or Marp use.
→ `sips -s format png input.webp --out input.png`.
