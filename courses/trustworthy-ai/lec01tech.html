A Threat Model Is a Tuple

"Who, what they know, what they can do" is three coordinates.

Threat model

A triple $(\mathcal{G},\, \mathcal{K},\, \mathcal{A})$: the adversary's goal $\mathcal{G}$, their knowledge $\mathcal{K}$, and their action set $\mathcal{A}$.

"Is it secure?" is only well-posed once $(\mathcal{G},\mathcal{K},\mathcal{A})$ is fixed.

Assume the Attacker Knows the System

Set the knowledge $\mathcal{K}$ to the worst realistic case.

Kerckhoffs's principle

Security must hold even when everything about the system is public — except one small secret (a key, a random seed).

  • White-box: $\mathcal{K}$ includes the weights $\theta$ and gradients
  • Black-box: $\mathcal{K}$ is only the input–output map

"Security through obscurity" is not a threat model.

Knowledge $\mathcal{K}$ × timing (the action set $\mathcal{A}$) locate the attack.

The Adversarial ε-Ball

Inference-time attacks live in a bounded perturbation set around $x$.

$$\max_{\|\delta\| \le \varepsilon} \; \ell\big(f_\theta(x + \delta),\, y\big).$$

The action set $\mathcal{A}$ is the ε-ball $\{\delta : \|\delta\| \le \varepsilon\}$: small enough to look unchanged, large enough to flip the label.

Goodfellow, Shlens, and Szegedy, "Explaining and Harnessing Adversarial Examples", ICLR 2015.
