Lecture 7 — Interpretability & Explainability · Speaker Script

One entry per slide, in order. Section headers match slide titles.

Interpretability & Explainability

Welcome to Lecture 7. Today's question is simple to ask and hard to answer: a model gives an answer, but can it tell us why? We want to open the black box and see the reasoning, because a right answer with an unknown reason is hard to trust.

Key takeaway: Trust needs not just correct answers, but understandable reasons.

Contents

Six steps: why opening the box matters, feature attribution, probing and attention, mechanistic interpretability, sparse autoencoders and steering, then the uses and limits.

Key takeaway: From inputs, to internals, to readable mechanisms we can steer.

01 — The Black Box

First section. The framing: modern models are accurate but opaque, and opacity is itself a trust problem.

Key takeaway: Opening the box is a trust requirement, not a luxury.

A Model Is a Black Box

A network maps input to output through billions of weights. It answers without explaining; the reasoning hides inside the numbers. Accuracy on its own does not earn trust.

Key takeaway: A right answer with an unknown reason is not enough.

Why Open It Up

Explanations serve four needs: debugging failures, auditing for bias, complying with a right to explanation, and deciding when to rely on the model at all.

Key takeaway: One explanation, four payoffs: debug, audit, comply, trust.

The Husky and the Wolf

The classic cautionary tale from the LIME paper — and note it was a deliberately rigged demo: the authors trained the classifier on photos where every wolf had snow in the background, so it learned to detect snow, not the animal. Graduate students who saw the explanations went from 10-of-27 trusting the model to 3-of-27.

Key takeaway: Explanations expose shortcuts that accuracy alone hides.

Two Routes to Understanding

Two strategies. Intrinsic interpretability makes the model readable by design, like a short decision tree or a linear rule. Post-hoc interpretability explains an already-trained black box from the outside.

Key takeaway: Intrinsic is readable by construction; post-hoc is approximated after the fact.

The Accuracy Trade-off

Historically, the most readable models fit worse, and the most accurate ones were opaque. That trade-off is real but softening, as new tools make large models more interpretable.

Key takeaway: Simplicity once cost accuracy, but the gap keeps narrowing.

The Rudin Objection

Cynthia Rudin's famous 2019 argument: for high-stakes decisions like bail, parole, or medical triage, the trade-off is often overstated, and we should build models that are interpretable by design rather than explain black boxes after the fact — a wrong post-hoc story can cause real harm.

Key takeaway: For high-stakes calls, some argue for interpretable-by-design models, not explanations.

Explanation Is Not the Model

A crucial caveat for the whole lecture: a post-hoc explanation is a story about the model, not the model itself. The story can be persuasive yet wrong.

Key takeaway: An explanation can be convincing and still be unfaithful.

02 — Feature Attribution

Second section. The most common family of tools: which input features moved this particular prediction?

Key takeaway: Attribution scores the inputs behind a single decision.

The Attribution Question

For one prediction, attribution asks which input features pushed the output up or down. Each feature gets a signed score: positive features help the outcome, negative ones hurt it.

Key takeaway: Attribution gives each feature a signed share of one prediction.

Attribution as a Bar Chart

Concretely: a loan model rejects an applicant, and attribution shows the contributing features as a bar chart. Low income and high debt push toward reject; a long credit history and home ownership push the other way.

Key takeaway: A bar chart of pushes makes one decision legible.

LIME: Local Surrogate

LIME, Local Interpretable Model-agnostic Explanations: perturb the input, watch the output change, fit a simple linear model in that neighborhood, and read its weights. It works for any model because it only needs query access.

Key takeaway: LIME fits a simple local model and reads its weights.

Local, Not Global

LIME explains a single prediction. The true decision boundary may be wildly curved, but near one point a straight line approximates it well. Stress that the explanation is only valid locally.

Key takeaway: A LIME explanation holds near one point, not everywhere.

SHAP: Fair Credit

SHAP, SHapley Additive exPlanations, borrows the Shapley value from cooperative game theory. Treat each feature as a player on a team; its score is its average marginal contribution to the prediction.

Key takeaway: SHAP splits the prediction fairly using game theory.

The Shapley Value

The Shapley value $\phi_i$ adds feature $i$ to every possible subset $S$ of the other features and averages the gain in prediction. The weights make the split fair across all orderings.

Key takeaway: $\phi_i$ is feature $i$'s averaged marginal contribution.

Why SHAP Is Trusted

The Shapley value is the unique attribution that satisfies all the fairness axioms at once: the scores sum to the prediction, a useless feature gets zero, and identical features get equal credit.

Key takeaway: SHAP is the only rule meeting every fairness property.

SHAP on a Loan Model

A natural Colab demo: train a gradient-boosted model on tabular loan data, run SHAP on one rejected applicant, and read the signed bars. A few lines with shap.Explainer produce the chart.

Key takeaway: SHAP on tabular data is a short, hands-on notebook.

Saliency on Images

For images, attribution becomes a heat map over pixels. Bright regions are the pixels the prediction leaned on most.

Key takeaway: A saliency map highlights the pixels behind the label.

Gradient Saliency

The simplest saliency map is the absolute gradient of the output with respect to each input pixel. A large slope means a small change in that pixel would move the score a lot, so the pixel matters.

Key takeaway: Big gradient at a pixel means that pixel drove the score.

Beyond Raw Gradients

Raw gradients have a known weakness: once the model is confident, the local slope flattens and an important pixel can score near zero. Integrated gradients fixes this by averaging the gradient along the path from a blank baseline to the actual image — the whole climb, not one point.

Key takeaway: Integrated gradients averages the slope along a path, giving sturdier scores.

Saliency on Your Photo

A Colab demo: load a pretrained image classifier, backpropagate to the input pixels, and overlay the gradient as a heat map. Students see directly what the model looks at.

Key takeaway: A few backprop lines reveal where the model is looking.

What Attribution Answers

Attribution tells us which inputs moved this output, with sign and rough size, and it spots obvious shortcuts. It does not reveal the internal mechanism, does not guarantee faithfulness, and does not explain the whole model.

Key takeaway: Attribution is useful but bounded, and not automatically faithful.

Attribution Can Mislead

A sobering result: some popular saliency maps barely change when you randomize the model's weights. If the explanation does not depend on the model, it cannot be explaining the model. This is the sanity-check critique.

Key takeaway: A map that ignores the weights is not explaining the model.

03 — Probing & Attention

Third section. We stop looking at inputs and start looking inside, at the hidden layers and the attention patterns.

Key takeaway: Now we inspect the model's internal state, not just its inputs.

Inside the Hidden Layers

Each layer turns the input into a vector of activations: the model's internal state at that depth. Attribution stays at the input; probing asks what a hidden layer has already figured out.

Key takeaway: Hidden activations are where internal understanding lives.

Linear Probes

A linear probe trains a tiny classifier on a frozen layer's activations. If a simple linear readout can recover a concept, like part-of-speech or sentiment, then that concept is present in the layer.

Key takeaway: A probe tests whether a concept is linearly readable from a layer.

Reading the Probe

An important caveat: a high probe accuracy is suggestive, not proof. The concept being decodable does not mean the model uses it, and a powerful probe can simply learn the concept itself.

Key takeaway: Decodable is not the same as actually used.

Attention Weights

A transformer lets each token attend to other tokens. Visualizing attention shows, for instance, the pronoun "it" attending to the noun "cat". Thicker lines mean more attention weight.

Key takeaway: Attention maps show which tokens each token looks at.

Attention Looks Like Explanation

It is tempting to read attention as what the model used: a pronoun attends to its noun, a verb to its subject. The picture is intuitive, which is exactly why we should be careful.

Key takeaway: Attention feels like an explanation, but feeling is not evidence.

Attention Is Not Explanation

The cautionary result: you can often find very different attention patterns that produce the same output. If the weights can be swapped without changing the answer, they are not the reason for the answer. Treat attention as a clue, not a verdict.

Key takeaway: Attention weights are a hint, not a faithful explanation.

...Is Not Not Explanation

The same year brought a rebuttal: whether attention "explains" depends on what you mean by explanation, and the adversarial attention patterns fail simple diagnostics. Attention can still be useful evidence. Present the pair as a live scientific debate, not a settled verdict.

Key takeaway: The attention debate is open; treat attention as evidence, not proof either way.

04 — Mechanistic Interpretability

Fourth section, and a shift in ambition: instead of describing behavior, we try to reverse-engineer the actual computation the network performs.

Key takeaway: Mechanistic work aims to decompile the model, not just describe it.

A Different Goal

Mechanistic interpretability treats the network like code to be decompiled: reverse-engineer it into algorithms a human can read, rather than producing an external summary of behavior.

Key takeaway: The goal is human-readable algorithms inside the weights.

Circuits

A circuit is a small subgraph of the network that performs one job. The Distill circuits work showed, in vision models, how edge detectors feed curve detectors that feed a circle detector, building recognizable structure step by step.

Key takeaway: Circuits are readable sub-computations stitched into the model.

Neurons as Concepts

In vision models, some neurons fire for one clear idea: a curve detector, a dog-head detector. Wired together they recognize parts of objects, evidence that there is structure, not chaos, inside.

Key takeaway: Some neurons map cleanly to single human concepts.

The Transformer Framework

A 2021 Anthropic paper gave transformers a clean mathematical description: attention heads as composable operations reading from and writing to a shared residual stream. This framework made circuit-style analysis possible for language models.

Key takeaway: Heads communicate through a shared residual stream.

Induction Heads

The flagship circuit found in language models. An induction head, built from two cooperating attention heads, implements a copy rule: having seen "A B" earlier, when "A" recurs it predicts "B".

Key takeaway: Induction heads copy patterns seen earlier in the context.

Induction in Action

Concretely, if "Harry Potter" appeared earlier and "Harry" recurs, the induction circuit finds the earlier match and copies what followed, predicting "Potter". This is the engine behind copying from context.

Key takeaway: Find the earlier match, copy what came next.

Why Induction Matters

Induction heads underlie much of in-context learning. They emerge sharply at a specific point in training, and their arrival coincides with a jump in few-shot ability. A behavior explained by a concrete mechanism.

Key takeaway: A traced circuit explains the rise of in-context learning.

The Polysemantic Wall

The bad news: most neurons are not one clean concept. A single neuron tends to fire for many unrelated things, a property called polysemanticity, which blocks naive one-neuron-one-meaning reading.

Key takeaway: Most neurons mix many meanings and resist easy reading.

Superposition

The reason for polysemanticity: the model packs more features than it has neurons, so features overlap in the same dimensions and each neuron carries a mix. Like cramming too many ideas into too few words.

Key takeaway: Superposition crams many features into few neurons.

05 — Sparse Autoencoders & Steering

Fifth section, and the recent breakthrough: a way to pull the overlapping features apart into readable units, and then to turn them like dials.

Key takeaway: Sparse features make internals readable and controllable.

Unpacking Superposition

The idea: spread the activations into a much wider space and force only a few units to be active at once. With few actives, each one can carry a single clean meaning. We trade a few crowded dimensions for many clear ones.

Key takeaway: Widen and sparsify to separate the tangled features.

The Sparse Autoencoder

A sparse autoencoder, or SAE, widens the neuron activations into a large, sparse layer and then rebuilds them. The few active units in the wide layer turn out to carry readable meanings.

Key takeaway: An SAE expands activations into sparse, readable features.

Monosemantic Features

The 2023 result: each SAE feature fires for one human concept, like DNA sequences, legal language, or base64 text. Monosemantic means one feature, one meaning.

Key takeaway: SAE features are monosemantic: one feature, one concept.

Scaling Up

In 2024 this scaled to a production model. Millions of features were extracted from Claude 3 Sonnet, spanning cities, famous people, code bugs, and scam emails, including a now-famous Golden Gate Bridge feature.

Key takeaway: The method scaled to millions of features in a real model.

Feature Steering

A clean feature is not only readable, it is a dial. Turning a feature up or down lets us change the model's behavior in a targeted way.

Key takeaway: A readable feature is also an adjustable control.

Golden Gate Claude

The vivid demonstration: amplify the Golden Gate Bridge feature and the model steers nearly every answer toward the bridge. The intervention causally proves the feature is real and not just a correlation.

Key takeaway: Steering is a causal test that the feature is real.

A Steering Widget

A Colab demo: pick a known feature from an open sparse autoencoder, slide its strength from off to high, and watch the generated text shift in real time. The interactivity makes the abstraction concrete.

Key takeaway: A live slider shows steering changing the output.

Steering for Safety

The same dials could work in reverse: the scaled SAE found safety-relevant features for deception, bias, and scam emails, which could be watched or damped. Interpretability stops being only a viewer and becomes a control knob — though this is still early-stage research, not deployed practice.

Key takeaway: Steering could turn down harmful behavior, but it is still early days.

06 — Uses & Limits

Final section. We step back to the practical payoff and the hard limit that shadows every method here.

Key takeaway: Real uses exist, but faithfulness is the recurring catch.

What It Buys Us

Three concrete payoffs: debugging, tracing a wrong answer to its cause; auditing, surfacing bias and hidden shortcuts; and safety, detecting and steering harmful behavior.

Key takeaway: Interpretability pays off in debugging, auditing, and safety.

What the Law Demands

The GDPR touches automated decisions in two places: Article 22 gives a right not to be subject to a solely automated decision with legal or similarly significant effect, and Articles 13–15 give a right to meaningful information about the logic involved. Think loans, hiring, insurance.

Key takeaway: The GDPR grants a right against automated decisions and to information about the logic.

A "Right to Explanation"?

The famous phrase is weaker than it sounds: it appears only in a non-binding recital, and legal scholars — most famously Wachter, Mittelstadt, and Floridi — argue the GDPR does not actually grant it. The EU AI Act closes some of the gap: its Article 86 gives people affected by high-risk AI decisions a right to a clear, meaningful explanation.

Key takeaway: The GDPR "right to explanation" is contested; the AI Act adds an explicit one for high-risk systems.

The Faithfulness Problem

The central limit: an explanation is faithful only if it matches the real cause of the decision. A plausible explanation can still be wrong about why the model decided.

Key takeaway: Plausible and faithful are different; only faithful counts.

Models Can Rationalize

A specific danger with language models: ask them to explain themselves and they produce fluent, convincing reasons that may not reflect the actual computation. A confident self-explanation is not a faithful one.

Key takeaway: A model's self-explanation needs its own audit.

Always Sanity-Check

Practical discipline: before trusting an explanation, test it. Randomize the weights and see if the map changes; intervene and see if behavior actually shifts; hold out cases and see if the explanation predicts them.

Key takeaway: Trust an explanation only after it survives a real test.

Frontier: Attribution Graphs

In 2025 Anthropic's circuit-tracing work produced attribution graphs that follow a whole computation: asked for the capital of the state containing Dallas, Claude 3.5 Haiku activates "Texas" and then "Austin"; writing rhyming poetry, it picks the rhyme word ahead of time. The tools were open-sourced in May 2025 and graphs can be explored interactively on Neuronpedia.

Key takeaway: Circuit tracing now maps full computations, and the tools are public.

Frontier: Does the Model Say What It Thinks?

Reasoning models print a chain of thought, but it is not automatically faithful: slip a hint into the prompt and models that use the hint usually admit it in under 20% of cases. Chain-of-thought is one more explanation to audit, not ground truth about the computation.

Key takeaway: A model's printed reasoning can hide what actually drove the answer.

Frontier: An MRI for AI

Interpretability is now framed as a safety race: Dario Amodei's 2025 essay argues we must understand models before they become overwhelmingly powerful, sets a goal of interpretability reliably detecting most model problems by 2027, and pictures it as an MRI run on every model.

Key takeaway: The field's ambition is interpretability as a deployment requirement, on a deadline.

Key Takeaways

To close: accuracy alone does not earn trust; attribution tells us which inputs moved an output; mechanistic work reverse-engineers the algorithm; sparse features give readable dials we can steer. And faithfulness is the test every explanation must pass.

Key takeaway: Aim for explanations that are faithful, not merely convincing.

Why?

Closing slide. The whole lecture in one word: moving from a right answer to a readable reason.

Key takeaway: The goal of interpretability is a reason we can read and check.
