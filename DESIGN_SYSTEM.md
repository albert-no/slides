# Talks design system

Normative authoring rules for slide decks. Academic conference talks and master-level lectures, math-heavy (rigorous statement + rigorous proof + intuition pass), visually minimal (short phrases, never sentences).

**Canonical order.** `reference/deck.css` > this file > `GOTCHAS.md`. This file says *how to author*; GOTCHAS says *what broke and why*. For exact CSS behaviour read `reference/deck.css` — never paraphrase it here.

**Never duplicate `reference/`.** Decks `<link>` to `colors_and_type.css` (fonts + tokens), `deck.css` (engine + components), `deck.js` (scale / nav / footer injection).

**Visual weight floor.** Kangwook Lee's BLISS deck (captures: `reference/kangwook1.png`–`kangwook4.png`). Rendering smaller than that usually means a per-deck `<style>` shadowed the canonical tokens.

## 1. Priorities (ranked, non-negotiable)

Lower number wins when rules conflict.

### 0. Font sizes

Important content → body size. Unimportant content → the companion `-note.html`, **never** shrunk to fit.

- Don't redefine `p`, `li`, `h1`–`h3`, `.subtitle`, `.cite`, `.small`, `.tiny`, `.math-block`, `.muted`, or `.code-block` font-size in a deck `<style>`. Don't put inline `font-size` on prose.
- `.tiny` is banned everywhere. `.small` on prose is banned (paragraphs, list items, captions, anything inside `.highlight` / `.card` / `.cols` / `.grid-*` / `.math-block` / under a `<table>`).
- Only two on-slide slots take sub-body text: `.cite`, and `.small` on a non-crucial diagram sub-label when compression breaks the layout.
- **De-emphasis is by color, not size.** `<em>` and `<p class="muted">` stay body size and render gray. `.muted` is color-only — never give it a font-size.
- Component-internal text (pill labels, token chips, code blocks) keeps its native size — design tokens, not overrides.
- Cramped slide → cut content or split. There is no slide budget.

### 1. Density

**Hard ceiling 7×7**: ≤7 visual lines per slide, ≤7 words per line. Soft target ≤40 words of body prose per content slide.

- **Phrases, not sentences.** Telegraphic noun phrases. Drop connectors ("this means", "in other words", "essentially") and soft qualifiers ("very", "quite", "fairly"). Applies to `h2` titles too — 3–6 abstract words, not action-title sentences.
- **Math is not prose.** Theorems, definitions and equations in a `.math-block` don't count toward the 40 words.
- **One claim per line.** Multiple claims joined by periods → separate `<p>` siblings, or a `<ul>` at 3+. Applies inside `.highlight` / `.card`.
- **Math-comma-math is banned.** "For large $N$, $N\sigma^2$ dominates" — two glyphs across a comma read as one expression. Insert a noun ("the second term $N\sigma^2$") or restructure. Math merely *starting* a clause is fine; the failure needs math on *both* sides.
- **No mid-sentence em-dash.** Wraps badly and orphans the dash. Use a colon + `<br>`, or two `<p>`. Safe only inside technical glyphs (`7–8B`), `.cite` lines, and `h2` titles ("Proof — MGF bound").
- **Pin a number next to a closed form.** `$R(D) = 1 - H_b(D)$, &nbsp;$R(\tfrac14) \approx 0.189$ bits`.

**When prose visibly wraps, in this order:** compress to noun phrases → split at a sentence/colon boundary into two `<p>` → glue an inseparable phrase with `&nbsp;` → never break within a phrase. `<br>` as an orphan-shim is banned; `<br>` at a deliberate internal clause break is allowed, rarely.

### 2. Overflow

Content fits 1280×720 and clears the auto-injected `.brand-footer` (bottom-left, ~40 px). Footer collision counts as overflow.

Overflowing → compress (Priority 1) → split the slide → move secondary detail to `-note.html`. **Never** shrink type. **Never** compress vertical rhythm (`margin` / `padding` / `line-height`) on prose.

**Element budget.** `h2` + `divider` + **at most 5 child elements**. `.math-block` = 1. `<table>` = its row count. `.highlight` = 1 regardless of its internal `<p>` count. **`.math-block` + `<table>` + `.highlight` together is already over — split before previewing.**

**Vertical budget.** Available for body content ≈ **430–470 px** (720 − 56 top − 48 bottom padding − header block − bottom reserve).

| Element | Cost |
|---|---|
| `h2` + `.divider` header block | ~110 px |
| Prose line (`p` / `li`) | ~40 px |
| `.math-block`, single line | ~80 px |
| Each extra `aligned` row | +50–60 px |
| `\underbrace` under an equation | +25–30 px |
| `<table>` row | ~55 px |
| `.highlight`, one line | ~70 px |
| `.card` wrapper | +~30 px over content |
| Image | 470 px solo · 380–430 px beside bullets · 320–380 px stacked |
| Bottom reserve (footer / footer+cite) | ~40 px / ~80 px |

Worked ceiling: one 3-line `aligned` (~200) + one 1-line `math-block` (~80) + two prose lines (~80) + a `.highlight` (~70) ≈ 430 px — exactly at the edge. **At most one 3-line `aligned` block plus one one-line `math-block` per slide.** Beyond that: split.

Multi-slide proofs recover with a `Proof (continued) — <paraphrase>` heading plus a one-line recap (§5).

### 3. Empty space

Empty space at the **bottom** is fine. Empty space in the **middle** is not.

- No `.spacer*` padding. Trust element margins.
- Don't wrap 2–3-line content in `.cols` + `.card` — `.cols` stretches short cards into hollow boxes. Use `.grid-2` with bare `<h3>` + `<p>`.
- Too sparse → add a real closing element (summary math-block, `.highlight` takeaway, recall card) or merge. Never pad.

### Style rules

1. **One idea per slide, one exhibit per slide** — one chart, table, diagram, theorem, proof chunk, or equation block.
2. Speaker narrates; the slide is a visual anchor.
3. `**strong**` → Yonsei Blue. `*em*` → muted gray (never italic — no italic face exists). A whole subordinate line → `<p class="muted">`, still body size.
4. Key insight → `<div class="highlight">`, **max one per slide**.
5. Math: inline `$…$`, display `$$…$$` inside `.math-block`.
6. Attribution → `<div class="cite">` at the bottom, never a side card (§6).
7. **Ghost deck test.** Read only the `h2` sequence — it must outline the arc. Fix the outline before drafting bodies.
8. **Spell out acronyms on first use** — `SSCD (Self-Supervised Copy Detection)`. Canonical ones (LLM, MIA, DP, KL, MSE) exempt. In the body where the term appears, not a glossary slide.
9. **Aim for a visual on every slide.** Ask "what's the picture?" before "what are the bullets?" (§8). Doesn't override rule 1 — *a* visual, not a collage.
10. **Self-contained slides.** No "next week", "previously", "(Wk N)", "see Lecture 3", "as we saw". Week indices belong only on a syllabus slide.

## 2. Deck anatomy

1. **Title** (`.title-slide`) — logo, `.pill` talk-type, h1, subtitle, speaker line.
2. **TOC** (`.toc-list`) — required at **3+ sections**; skip for ≲15-slide talks and tech supplements.
3. **Sections** — `.section-slide.left` numbered divider, then content. Centered `.bg-accent` only for dramatic interludes, not structural breaks.
4. **Recap** (optional, math decks) — the equation chain (§5), not re-bulleted outline.
5. **Closer** — `.end-slide`, tagged `no-footer`.

Dividers and TOC must agree: same names, same order, `01`-style numbering.

| Token | Value | Use |
|---|---|---|
| `--yonsei-blue` | `#003876` | Primary accent: `strong`, dividers, bullets, h2 underline |
| `--blue-light` | `#1a5296` | Cards, pill outlines |
| `--accent` | `#005baa` | Tertiary, sparing |
| `--charcoal` | `#1a1a1a` | Body text |
| `--gray-text` | `#666666` | Muted (`em`, `.cite`, subtitles) |
| `--slate` | `#e8ecf0` | Borders, table rules |
| `--light` / `--subtle` | `#f4f6f9` | Card / math-block / divider background |
| `--white` | `#FFFFFF` | Slide background |
| `--success` | `#2e8b57` | `ul.check`, `.token-safe` |
| `--warn` | `#d94040` | `.token-eos` |

**Color carries semantic load only if stable.** One role per color across the whole deck; never recolor for decoration.

| Color | Math meaning |
|---|---|
| `--yonsei-blue` | Being introduced / active step / focus term |
| `--charcoal` | Established / given / already proved |
| `--gray-text` | Future / unproven / parenthetical |
| `--success` | Equality that closes a chain / final claim |
| `--warn` | Counterexample / where the standard argument breaks |

**Type** — `'Yonsei', 'Noto Sans', Arial, sans-serif`. No italic face exists.

| Role | Size | Weight | Line height |
|---|---|---|---|
| `h1` | 3.6rem (4 title, 4.2 left-section) | 700 | 1.08 |
| `h2` | 2.7rem | 700 | 1.12 |
| `h3` | 1.85rem | 700 | 1.22 |
| `p`, `li` | 1.55rem | 300–400 | 1.5 |
| `.subtitle` | 1.75rem (1.9 title) | 300 | — |
| `.cite` | 0.85rem | — | — |
| `.small` | 1.15rem | — | gated (Priority 0) |
| `.tiny` | 0.95rem | — | banned |
| `.muted` | = body | 300–400 | color only, never a size step |
| `.code-block` | 1.25rem | 500 | 1.6 |

`text-wrap: balance` on headings, `pretty` on prose. Don't override.

**Spacing** — slide padding `56px 72px 48px` (title `72px 88px`); radii 12/10/8/6px and `3.667em` (pill); viewport fixed 1280×720 scaled by JS transform; `fadeIn` 0.4s staggered 0.06–0.30s on `.slide.active` children, disabled in print. **No other animation language** — build-ups are multi-slide progressions, never CSS keyframes.

## 4. Components

All defined in `reference/deck.css`. Reuse; don't invent.

- **Containers** — `.slide`, `.title-slide`, `.section-slide`, `.section-slide.left`, `.end-slide`
- **Backgrounds** — `.bg-light`, `.bg-accent` (inverts component defaults; dividers and statement slides only)
- **Blocks** — `.card`, `.highlight` (max 1/slide), `.pill` / `.pill-fill`, `.divider`, `.math-block`, `.code-block` (`.kw` `.fn` `.cm` `.str`), `.diagram-flow` / `.diagram-box` (**full slide width only**), `.cite` (+ `.cite-left` / `.cite-right`), `.brand-footer` (auto)
- **Token chips** — `.token-mask` / `-gen` / `-fixed` / `-eos` / `-safe` / `-pad` / `-pad2` / `-pad3`
- **Layout** — `.cols`, `.col-2-3` / `.col-1-3`, `.grid-2`, `.grid-3`
- **Lists** — `ul` (blue dot), `ul.check` (green ✓), `ul.arrow` (blue →), `ul.num` (numbered badge)
- **TOC** — `.toc-list` / `.toc-item` / `.toc-num` / `.toc-rule` / `.toc-label` / `.toc-sub`
- **Engine (auto-injected, hidden in print)** — `.progress-bar`, `.slide-num`. `no-footer` is consumed by `deck.js`, not CSS — don't "clean it up".

## 5. Math-heavy talks

**Pairing pattern** for results the audience must understand: Intuition (1 slide, picture + why to expect it) → Theorem (1, rigorous statement) → Proof (1–N) → Discussion (optional). Theorem-only is fine for results they just need to know exist.

**Theorem** — `.card` with `<h3>Theorem N (Author, Year).</h3>`, assumptions in a `<p>`, assertion in a `.math-block`, source in `.cite`.

**Proof** — one logical step per visual line; multi-slide rather than shrunk. Continuation heading template:

```
Proof (continued) — <short paraphrase of the continuing step>
```

e.g. "Proof (continued) — Divide by the marginal". Never ship a bare `Proof (continued)`; the paraphrase is what reorients a reader landing mid-proof. Follow it with one recap line, then the new math.

**Intuition** — one visual metaphor, `.cols` with phrases left and a sketch right. Color and build-up pay off here.

**Build-up (controlled "animation").** Auto-cycling animation is banned — it dictates pacing the speaker doesn't control. Instead duplicate the slide N times; on copy *k* color the first *k* steps `--yonsei-blue` (active/established) and the rest `--gray-text` (upcoming). Title as "… (2 of 4)". Tag the sequence with a per-deck no-fade class so advancing doesn't flash:

```html
<style>.<deck>-no-fade.active > * { animation: none !important; }</style>
```

**Stacked equations belong in one block.** Two related equations → one `.math-block` with `\begin{aligned}`, not two adjacent blocks (adjacent blocks add ~60 px of gap and read as unrelated ideas).

*Exception*: promote a **key conclusion** to its own block so it lands separately — the gap becomes signal.

*Tight-margin rescue*, when a proof slide is tight specifically from math-block chrome: inline `style="margin: 8px 0;"` on the affected blocks, or a scoped per-deck class (`.d3-tight .math-block { margin: 8px 0; }`) on the flagged slides. Never touch the global `.math-block` rule; never apply deck-wide by default. Still over budget → split.

**Multi-step proof (4+ steps).** Setup → Outline (the *target* in a math-block, then an `<ol>` of step labels) → Step 1…k, one per slide → Recap.

Recap is a single `aligned` block showing the unified chain, each step labelled above its relation symbol — **never the bulleted outline again** (outline previews *labels*, recap shows the *chain*):

```latex
&\stackrel{(1)}{\approx}\; …          %% numeric: cross-references a named step slide
&\stackrel{(\text{split})}{=}\; …     %% descriptive: names a non-obvious algebraic move
```

Use `\text{...}` for upright labels; keep each under ~25 characters. Mix freely — numeric where a callback helps, descriptive where the move *is* the explanation.

**Recipe-first derivation.** For a parameterized formula whose shape isn't obvious (DDIM's $\mu_n$, score reparameterizations): state the **recipe** with named unknowns and `\underbrace`-labelled ingredients → impose the **constraint** you actually want (one equation per unknown, surface the free parameters) → **read off** the resulting form. The student sees every coefficient come from a constraint. Don't use it when the formula has clean independent motivation (Bayes, KL, an established theorem).

**Substitution** — abstract form first, then the substitution arrow, then the concrete form. Never jump to the substituted form; the reader loses which result you invoked.

**Underbrace labels** — label the **per-term operand, not the whole sum**: `\sum_n \underbrace{(\cdots)}_{L_{n-1}}`, not `\underbrace{\sum_n \cdots}_{\sum L_{n-1}}`. The per-step object is what the reader reasons about later. Budget +25–30 px each.

**Recall before derive** — state prerequisite A as a self-contained fact (own paragraph + math-block), *then* derive B. Never hide A in a trailing "where …, known in closed form since $A$" clause.

## 6. Conventions

### Page numbering

`deck.js` counts **every** `<div class="slide">` — title, TOC, dividers, content, recap, closer. "Page N" = the Nth. Match slides by `<h2>` content, not number: numbers shift on every insertion. Build the map with `grep -n 'class="slide' <deck>.html` and rebuild after any insert/remove.

**One indicator only** — the bold `.slide-num` injected by `deck.js`. If a deck also carries a per-deck `.page-num` injector script (copied from an older sibling), delete the script and its CSS. Hidden in print by design.

### Citations

Format: `Authors (in venue order), "Title", Venue YYYY` — no arXiv ID unless asked. Use the **venue's** author order (PMLR / NeurIPS / journal TOC), not arXiv's; they differ. `et al.` acceptable for 4+ authors after first reference.

- **One dedicated line per citation.** Two papers → two lines (`<br>` inside one `.cite`, or two adjacent blocks). Never let a citation wrap mid-title.
- **Two length tiers**: theorem/lemma slide → full `Author et al., "Title", Venue YYYY.`; dense abstract-bullet slide → short `Author et al., DPO, NeurIPS 2023.`
- **Position** — bottom of the slide, satisfying in order: inside the rectangle → no overlap with body/images → no collision with `.brand-footer` (bottom-left, ~28 px in, ~180 px wide).
- **Escape hatches** when the centered 60% cap forces a wrap, lightest first: `.cite-left` (left, 92% cap, `bottom: 48px`, clears the footer) then `.cite-right` (right, 92%, `bottom: 18px`, only when the lower-left must stay clear). Both live in the deck's local `<style>` — copy from a deck that has them.
- **Figure citations** — `Author et al., Venue YYYY — Figure N.`

## 7. Patterns

**Markup lives in the exemplar decks, not here.** For any pattern below, open the cited file and copy the live markup — it is guaranteed current, this file is not. `reference/deck-skeleton.html` is the starter (cloned by `scripts/new-talk.sh`).

| Pattern | Structure | Copy from |
|---|---|---|
| Title slide | `.title-slide` + logo + `.pill` + h1 + `.divider` + `.subtitle` + speaker | `reference/deck-skeleton.html` |
| Content slide | `h2` + `.divider` + phrases + ≤1 `.highlight` | any exemplar |
| Section divider | `.section-slide.left` + `.section-num` + h1 + `.divider` + `.subtitle` | any exemplar |
| TOC | `.toc-list` › `.toc-item` › `.toc-num` + `.toc-rule` + `.toc-label`/`.toc-sub` | any exemplar |
| Closer | `.end-slide.no-footer` + `.big-word` + `.big-word-sub` | any exemplar |
| Three-pillar | `.grid-3` of `.card`; 2-column dichotomy → `.grid-2` bare `h3`+`p` (no card) | any exemplar |
| Math slide | prose + `.math-block`; `$$…$$` for `cases`/`align` | §5 |
| Code / pseudocode | `.code-block` with `.kw`/`.fn`/`.cm`/`.str`; escape `&lt;` | `lec02tech.html` |
| Diagram + math labels | HTML boxes for structure, SVG for arrows only | `dp8-fl.html` |
| Chain diagram | flex row of math spans, active edge blue, sleeping gray, `$\cdots$` nodes | `diffusion2-ddpm.html` |
| Recall card | `.card` `padding: 10px 16px` with `<strong>Recall (X).</strong>` | §5 |
| Inline exercise | plain `<p><strong>Exercise.</strong> …</p>` beside the fact | — |

**Rules the markup can't carry:**

- **Image + bullets** — `.grid-2` with `grid-template-columns:auto 1fr`, **`align-items: start`** (`center` floats short bullets midway down a tall figure and reads as a void). Height ceilings: beside bullets **380–430 px** · stacked with 1–3 bullets **380 px** · stacked with 4+ bullets or a `.highlight` **320–340 px** · single-figure slide **470 px**. Figures live in `<talk>/figs/`.
- **Image-first / description-follows** — when image+bullets overflows, split into a full-bleed image slide (`max-height: 460–500px`, one orienting line) then a "Reading the plot" slide with the bullets. Only for information-dense figures; a simple plot needs one slide.
- **Algorithm slide** — a single centered styled box, **never** `.code-block`, **no** side diagram (empty space below is fine). Per-deck `.<deck>-algo`: background `--light`, left border 3px `--yonsei-blue`, padding `16px 22px`, radius `0 10px 10px 0`, `max-width` ~880px (~1040px if a step carries long math). Step numbers need a counter — default `<ol>` markers are too small:

  ```css
  .<deck>-algo ol { margin:0; padding-left:0; list-style:none; counter-reset:step; }
  .<deck>-algo ol li { counter-increment:step; padding:8px 0 8px 56px; position:relative; line-height:1.45; }
  .<deck>-algo ol li::before { content:counter(step) "."; position:absolute; left:12px; top:8px;
                               font-weight:700; color:var(--yonsei-blue); width:36px; text-align:right; }
  .<deck>-algo ol li + li { border-top:1px solid var(--slate); }
  ```

- **Diagram dominates** — when asked to enlarge: (1) remove `max-width` from the `<svg>` (it belongs on the wrapper), (2) switch `.cols` to `.col-1-3` text + `.col-2-3` diagram, (3) bump a cramped viewBox (`220×130` → `~400×240`) so labels land at readable absolute sizes. Pure single-diagram slide: drop the cols, center at `max-width: ~960px`.
- **KaTeX overlays on SVG** — KaTeX skips SVG `<text>`, so math labels are absolute-positioned HTML spans over the SVG. Wrapper needs **both** `width: 100%` and `max-width` (max-width alone collapses to the SVG's intrinsic width). Position from the viewBox: `left = x/W·100%`, `top = y/H·100%`, `translate(-50%,-50%)` centered / `(-100%,-50%)` right-aligned. Pin the wrapper height to the viewBox aspect ratio when it hosts overlays. Sizes: axis labels `1.3–1.4rem/700`, threshold labels `1.0–1.1rem/600`, annotations `1.1–1.4rem/600`.
- **Inline exercise placement** — if the slide is at element budget, move the exercise to the sibling slide that *introduces* the fact it verifies, not the one that uses it. No trailing "Check It Yourself" slide, no `.exercise-list` styling.

## 8. Visual richness

**A deck of bullet lists is a failure mode.** Every content slide should carry an exhibit — diagram, schematic, chart, figure, table, or worked-math block — with text cut to a short framing line. Still **one** exhibit per slide; two visuals means two slides.

**Three sources, in priority order:**

1. **Real paper / public figures — preferred whenever a citable source exists.** If a paper or well-known post already has the figure (panda→gibbon, CLIP Figure 1, a BadNets trigger), capture and cite it rather than redrawing it: more credible, faster to get right. Reuse figures already vetted in sibling decks (`courses/privacy/lectures/03-memorization/figs/`) before re-fetching. **If you catch yourself building an SVG to express something a specific identifiable paper already illustrates, stop and capture the real figure.**
2. **Inline HTML + SVG concept diagrams** — only when no canonical source figure exists (a mechanism in your own words, a cross-paper comparison, an invented worked example). Structure in HTML/SVG; plain-text labels in `<text>` (never `$…$` — KaTeX skips SVG). One semantic color per role. Shipped examples: `courses/trustworthy-ai/lec01-introduction.html`, `lec02-privacy-dp.html`.
3. **TODO-marks** — wanted a visual but can't produce it now? Don't ship a bare slide. Leave `<!-- TODO real figure: <what>, <source paper / Fig N> -->`. First-class authoring debt; `grep -rn "TODO real figure"` finds them all.

**Make diagrams big.** Concept SVGs are routinely too small, and widening the wrapper alone leaves labels proportionally small — **bump both**. Full-width: wrapper `max-width: 820–920px`, `<text> font-size: 15–20`. Grid-column: `max-width: 360–440px`, `font-size: 13–16`. Primary labels bold.

### Figure-capture protocol

- **Crop the "Figure N:" caption out** — the speaker narrates it, and it pushes the figure off the slide. Keep `(a)`/`(b)` subcaptions only if referenced.
- **Cite the figure number**: `Author et al., Venue YYYY — Figure N.`
- **Prefer methodology figures** (plots, schematics, algorithm diagrams) over panels reproducing extracted training images or other third-party copyrighted content — describe those in text with strong attribution instead.
- **Crop tightly but with a few px of headroom** on every side; tabs and axis titles sit just outside the apparent bounding box. Flow: `pdftoppm -r 200 paper.pdf prefix`, crop with `sips --cropToHeightWidth H W --cropOffset Y X` or PIL, iterate twice, then **Read the resulting `figs/*.png` directly** — never trust the in-slide render, it may be cached.
- **Render at ≥180 DPI**; lower pixelates on a projector.
- **Store under `<talk>/figs/`** — `bundle.py` inlines `.png`/`.jpg`/`.svg`/`.webp`/`.gif`.
- **Downsample to ~1200 px max width before bundling** (`sips --resampleWidth 1200 figs/x.png --out figs/x.png`). Full-res captures base64-bloat the standalone past 50 MB. Authoring source unaffected.

## 9. Companion decks

**Note files** (`<deck>-note.html`). Detail worth recording that doesn't fit the slide: full-sentence explanations, skipped derivations, secondary examples, FYI context. One `<article>` per slide in slide order, headed by the slide's title. Plain HTML — no `.deck`/`.slide` engine — so KaTeX works the same. For lectures it's also the home of the **expanded proof** when the slide carries the short version.

> **Migration check.** Whenever you trim slide detail on the grounds that "it belongs in the note", open the paired `-note.html` in the **same edit** and confirm it's there or move it in. Trimming on the assumption it was already covered silently destroys content.

*Speaker-script variant*: one `<article>` per slide, `<h2>` = slide title, 1–2 sentences of what to say, a `Key takeaway:` line (blue `.kt` span). ≤~50 words each. A reading companion, not a transcript.

**Technical supplements** (`<deck>tech.html`) — for a course pitched below the math's native level. Main deck stays concept-first with at most **one glanceable formula per concept**; the supplement holds the formal version. Established across `courses/trustworthy-ai/`.

- **Stay/move rule.** *Stays*: a one-line single-expression formula read at a glance (`‖δ‖ ≤ ε`). *Moves*: anything multi-line, algorithm boxes with math, definition cards with quantifiers, Hessians, sums over subsets, likelihood ratios, z-statistics.
- **No back-references.** Leave a one-line plain-English statement so the main slide stands alone (Style rule 10). Don't point the main deck at the supplement — both are self-contained; discovery is via `OUTLINE.md`.
- **Structure.** Mirror the parent's `<head>`/`<style>`. Title slide "Lecture NN · Technical Supplement" → a "When to Use This" framing slide → formal content under §5 → closer. Proportionate: rich where there's real math, honestly short (4–6 slides) where there isn't. Never padded.
- Register every supplement in the leaf `OUTLINE.md`.

## 10. Outlines

Every folder carries an `OUTLINE.md`: **root** (folder map + topic→location quick-lookup), **folder** (subfolder map + cross-deck pointers), **leaf** (per-deck section table with `file:line`, named theorems with line numbers, paired-note summary). They are the canonical map for "where does proof X live" without grepping.

**Read-side — before writing or substantively rewriting any slide content:**

1. **In-track continuity.** Extending a series → open that folder's leaf `OUTLINE.md` and its parent. Confirm what notation, definitions, attacks, theorems and benchmarks earlier decks established. Don't redefine $(\varepsilon,\delta)$-DP if `01-dp/` covered it — "Recall (Lecture X)" instead. If a prerequisite was *not* covered, decide explicitly: one-slide recap, point to the prior deck, or defer.
2. **Cross-folder reuse.** Topics that live in more than one track (diffusion in `infotheory/07-diffusion/` vs `privacy/02-generative/`; DP in `01-dp/` vs `04-mia/`; MI bounds in `05-mi/` vs anywhere CLIP appears) → check the root quick-lookup table, then the other folder's leaf. Decide explicitly: reuse, adapt, "see also", or deliberately contradict with rationale. Don't rederive what track A already proved — link `<file>:<line>`.

When an entry is too coarse to answer the question, descend to the cited `<file>:<line>`. The outline points; it doesn't replace reading the deck.

**Write-side (non-negotiable).** Any edit that changes a section boundary, line range, or named-theorem location updates the corresponding `OUTLINE.md` **in the same change**. Add a slide → add the entry; remove → remove; rename a section → rename everywhere it's cited (leaf, folder, root). Bulk renumbering after a multi-slide insertion is part of the edit, not a follow-up. New deck → add a stub entry *before* writing slides.

Stale outlines are worse than none — they mislead. If you can't locate a topic from them, fix them rather than working around them. `python3 scripts/outline-lint.py` verifies every cited `file:line` exists and is in range; it cannot check that the line still holds the *claimed* content, so spot-check after big restructures.

## 11. No-toolchain fallback

The canonical loop is headless Chrome → PDF → `pdftoppm` → PNG → visual read (`/audit-and-edit-deck`), plus `lint-deck.py` / `find-wordy.py` / `outline-lint.py`. **Always prefer it.** Only after `command -v google-chrome pdftoppm python3 mutool convert gs` comes up empty and nothing can be installed:

1. **Slide map by grep, never memory.** `grep -n 'class="slide' <deck>.html`; Nth match = page N. Rebuild after every insertion or removal.
2. **Overflow by arithmetic.** Apply the §1 Priority-2 px table to every slide you touch; past ~430–470 px, split *now*. The element budget is the fast pre-filter.
3. **Lint by targeted grep:**
   - balanced divs — `grep -o '<div' … | wc -l` vs `</div>`
   - literal `<` in math (garbles every later slide) — `grep -nE '\$[^$]*<[a-zA-Z]'` and the `$$` variant → replace with `&lt;`
   - KaTeX delimiter escape — `grep -c "'\\\\("` must be ≥1
   - unknown classes — cross-check against `deck.css`, the deck's `<style>`, **and** `deck.js` (`no-footer` lives only in JS)
   - banned type — `grep -n 'class="[^"]*tiny'`, `.small` on prose, inline `font-size`
   - mid-sentence dashes — `grep -nE ' — | -- | – '` should hit only `.cite` and `h2`
   - `$` inside SVG `<text>` — never renders
4. **OUTLINE pointers** — `sed -n '<N>p' <file>` for each touched `file:line`.
5. **Flag the caveat.** This cannot catch visual overlap, squashed math spacing, or drifted SVG overlays. Say so explicitly and recommend a real audit once tooling exists.
